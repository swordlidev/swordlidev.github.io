> **本文解决一个问题**：当叙事从「人提示、AI 写代码」（vibe coding）转向「AI 自己规划、实现、迭代」（agentic engineering），技术压力会集中到三处——长上下文 × 长时序的推理成本、agent rollout 长尾造成的 GPU 空转、可验证真实工程环境的稀缺。
>
> GLM-5 对这三件事各给了一条主线：**DSA 稀疏注意力**、**全异步解耦 RL**、**环境规模化流水线**。本文按这三条主线拆解，并把全文最实用的两段单独拎出来：DSA 在 RL 阶段的踩坑记录，以及 SWE-rebench 上那个诚实的对照。
>
> 论文：*GLM-5: from Vibe Coding to Agentic Engineering*（Zhipu AI & 清华大学，arXiv:2602.17536v2）。模型：744B 总参 / 40B 激活，MoE + MLA + DSA，28.5T token。

## 一、一句话定位

> **概念速览**
> - **Vibe coding**：人用自然语言提示、AI 吐代码片段，人还是循环的主体（审阅、粘贴、调试）。
> - **Agentic engineering**：人只给目标，AI agent 自己规划、改文件、跑测试、看报错、再迭代。
> - **ARC**：本系列对 **A**gentic（工具使用与长时序执行）、**R**easoning（推理）、**C**oding（编码）三类能力的合称。
> - **MoE（混合专家）**：把前馈层拆成许多「专家」，每个 token 只路由到其中少数几个。于是模型可以很大（**总参数**），但单次前向只算一小部分（**激活参数**）。

[GLM-4.5 的叙事](/blog/glm-4-5-arc-foundation-models/)是「把 ARC 统一进一个 MoE」，GLM-5 换了一层：**从「人提示、AI 写代码」转向「AI 自己规划、实现、迭代」**。这个转向把技术压力集中到三个地方，也正好对应全文三条主线：

| 压力 | 回应 |
|---|---|
| 长上下文 × 长时序的推理成本爆炸 | **DSA**（DeepSeek Sparse Attention）+ MLA-256 + 参数共享 MTP |
| Agent rollout 长尾导致 GPU 大量空转 | **全异步解耦 RL 基础设施** + 异步 off-policy 稳定化算法 |
| 可验证的真实工程环境太少 | **环境规模化流水线**（>10k SWE 环境、数千终端环境、WKG 搜索题） |

结果：Artificial Analysis Intelligence Index v4.0 拿到 **50 分**（GLM-4.7 为 42），**首个达到 50 的开源权重模型**；LMArena 的 Text / Code 双榜开源第一；8 个 ARC benchmark 平均较 GLM-4.7 提升约 20%，整体与 Claude Opus 4.5、GPT-5.2 (xhigh) 同档，优于 Gemini 3 Pro。

## 二、架构：把「便宜」做成设计约束

> **概念速览**
> - **KV cache**：生成时每个历史 token 的 Key/Value 都要缓存复用。上下文越长，这块显存与带宽越是瓶颈，所以注意力的各种变体基本都在抢同一件事——**把 KV 压小**。
> - **GQA（分组查询注意力）**：多个查询头共用一组 KV，是当前最常见的省 KV 方案。
> - **MLA（多潜在注意力）**：把 KV 压成一个低维「潜在向量」再按需还原，省得比 GQA 更狠，但解码时点积维度更高，**换来了算力开销**。
> - **MTP（多 token 预测）**：训练时让模型一次预测后面好几个 token；推理时这些额外层充当「草稿模型」做**投机解码**，接受的 token 越多越快，指标叫**接受长度**。
> - **Muon**：一种对权重矩阵做正交化处理的优化器，GLM 系列的默认选择；它和具体架构会相互影响，这正是 2.2 节问题的来源。

### 2.1 规模与形状

| | GLM-4.5 | GLM-5 |
|---|---|---|
| 总参 / 激活 | 355B / 32B | **744B / 40B** |
| Dense / MoE / MTP 层 | 3 / 89 / 1 | 3 / **75** / 1 |
| Hidden dim | 5120 | 6144 |
| 专家总数 / 路由 / 共享 | 160 / 8 / 1 | **256** / 8 / 1 |
| 注意力头数 | 96 | **64** |
| QK / V head dim | 128 / 128 | **192 / 256** |
| Q-LoRA / KV-LoRA dim | – | 2048 / 512 |
| Indexer 头数 × 维度 | – | 32 × 128 |
| 词表 | 151,552 | 154,880 |

> 总参翻倍但**层数下降**（89→75 MoE 层）：目的是压低专家并行的通信开销。专家数翻到 256、激活只从 32B 涨到 40B，是「更稀疏而不是更厚」的典型选择。

### 2.2 MLA 的两处修补

MLA 省 KV cache，但论文坦率地报告了两个问题，并给出修法：

**问题一：在 Muon 优化器下，576 维 latent KV 的 MLA 打不过 GQA-8。**

修法 **Muon Split**：原配方对多头的 $W_{UQ}, W_{UK}, W_{UV}$ 整体做矩阵正交化；改为**按 head 切成小矩阵、各自独立正交化**，让不同注意力头的投影权重以不同尺度更新。

| | Hellaswag | MMLU | C-Eval | RACE | BBH | GSM8K | HumanEval |
|---|---|---|---|---|---|---|---|
| GQA-8 | 77.3 | 61.2 | 60.0 | 79.6 | 53.3 | 47.6 | 38.5 |
| MLA | 77.3 | 61.5 | 59.7 | 77.8 | 48.9 | 46.2 | 33.5 |
| MLA + Muon Split | 77.8 | 62.5 | 62.1 | 79.9 | 51.8 | 45.0 | 36.7 |
| MLA-256 + Muon Split | 77.4 | 62.0 | 59.9 | 79.6 | 51.3 | 47.5 | 36.6 |

附带收益：有了 Muon Split，**预训练全程注意力 logits 规模保持稳定，无需任何 clipping 策略**。

**问题二：MLA 解码贵**（576 维点积 vs GQA 的 128 维），且 DeepSeek-V3 的头数是按 H800 roofline 选的，换硬件就不成立。

修法 **MLA-256**：head dim 192→256，头数减 1/3。**训练计算量与参数量不变，解码计算量下降**，性能与 MLA 持平。

### 2.3 参数共享的 MTP

MTP 预测后 $n$ 个 token 需要 $n$ 层，显存与 KV cache 线性增长；DeepSeek-V3 只训 1 层却推理时预测 2 个 token，训推不一致压低了第二个 token 的接受率。

GLM-5 的做法：**训练时 3 个 MTP 层共享参数**——草稿模型显存与 DeepSeek-V3 持平，接受率更高。同样 4 步投机解码下，接受长度 **2.76 vs DeepSeek-V3.2 的 2.55**。

## 三、DSA：为什么是它，而不是 SWA / 线性注意力

> **概念速览：四种注意力，四种省法**
>
> 标准注意力（**dense / full attention**）让每个 token 看见前面**所有** token，计算量随长度平方增长（$O(L^2)$）。128K 上下文下这笔开销难以承受，于是有了三条省法：
>
> | 方案 | 怎么省 | 代价 |
> |---|---|---|
> | **SWA（滑动窗口注意力）** | 规定每个 token 只看最近的固定窗口（如 4096），窗口外一律不看 | 窗口是**固定位置**的，远处信息直接丢失；通常只把部分层换成 SWA、其余保留全注意力 |
> | **线性注意力 / GDN（门控 DeltaNet）** | 用一个带门控的**线性递归状态**替代 softmax 注意力，开销从平方降到线性 | 历史被压进固定大小的状态里，**细粒度检索会糊** |
> | **DSA（DeepSeek 稀疏注意力）** | 先用一个轻量的 **lightning indexer** 给所有历史 token 打分，只挑出 **top-k** 个真正相关的去算注意力 | 依赖 indexer 选得准；top-k 的实现细节会反噬 RL（见 6.3 节） |
>
> 关键区别：**SWA 按位置丢信息，线性注意力按压缩丢信息，DSA 按内容选信息**。前两者「丢掉的拿不回来」，DSA 则保留了访问任意远处 token 的可能性——这就是本节的论证主线。

DSA 的核心是用**内容感知的细粒度 token 选择**替代 $O(L^2)$ dense attention，长序列注意力计算降低约 **1.5–2×**，128K 上下文可以按一半 GPU 成本跑。前提认知：**长上下文中约 90% 的注意力条目是冗余的**。

### 3.1 用「继续预训练」切换注意力

从 mid-training 末期的 base model 出发，两阶段：

| 阶段 | 配置 |
|---|---|
| Dense warm-up | 1000 步，每步 14 条 × 202,752 token，lr 5e-3 → 2e-4（仅训 indexer） |
| Sparse adaptation | 沿用 mid-training 数据与超参，**20B token**，恒定 lr 1e-5 |

**20B vs DeepSeek-V3.2 的 943.7B**——训练预算小了 47 倍，但足够把 DSA 模型拉回 MLA 水平：

| | MQ-NIAH-128k | MV-NIAH-128k | SQuAD-128k | HotpotQA-128k |
|---|---|---|---|---|
| MLA | 100.0 | 95.5 | 79.7 | 66.3 |
| DSA | 100.0 | 97.0 | 86.0 | 63.0 |

进一步用同一份 SFT 数据微调 DSA / MLA 两个模型，**训练 loss 与评测分数打平**。

### 3.2 高效注意力消融：全在 GLM-9B 上做

| 方法 | RULER (64K/128K) | MRCR | HELMET-ICL | RepoQA |
|---|---|---|---|---|
| GLM-9B（全注意力） | 85.35 / 75.28 | 36.53 / 35.39 | 77.68 / 77.36 | 69.00 / 65.83 |
| SWA Interleave（固定交替） | 65.94 / 44.93 (**↓30.35**) | ↓6.50 / ↓6.56 | ↓1.72 / ↓13.84 | ↓18.67 / ↓26.50 |
| **SWA Pattern（搜索得到）** | 83.72 / 69.59 (↓5.69) | ↓1.51 / ↓1.81 | ↓1.20 / ↓2.76 | ↓6.67 / ↓14.66 |
| GDN | ↓8.59 / ↓11.28 | ↓4.81 / ↓5.17 | ↓0.80 / ↓2.52 | ↓3.50 / ↓9.66 |
| **SimpleGDN** | 81.76 / 67.03 (↓8.25) | ↓3.50 / ↓4.12 | **↑2.12 / ↑4.48** | ↓3.50 / ↓7.33 |

两个自研改进：

- **SWA Pattern（搜索式）**：受 PostNAS 启发，用 beam search（beam=8，每步定 2 层，40 层约 10 步收敛）在 **16K 上下文**上按 RULER 搜最优「哪些层换成 SWA」。最终 pattern 为 `SFSSFFSSSFFFFSSFSFFFFFFSFSFSSFSSFSFSSFSSS`（S=SWA，F=full）。**只在 16K 搜，却在所有长度上稳定泛化**；相比固定交替是天壤之别（128K：53.95 vs 6.51，无额外训练设定下）。
- **SimpleGDN**：为「最大化复用预训练权重」而做的极简线性化——**删掉 Conv1d 与显式 gating**，直接把预训练 QKV 投影权重映射进线性递归式。不引入额外参数，却优于 GDN。

**结论很硬**：无论搜索式 SWA 还是线性注意力，在细粒度检索上都有**不可消除的精度缺口**（RULER@128K 最多 −5.69，RepoQA@128K −7.33），即使一半层保留全注意力也如此。而 **DSA 在构造上是无损的**——lightning indexer 做 token 级稀疏但不丢弃任何长程依赖，因此可以应用到**所有层**。

小规模验证（GLM-4.7-Flash，RULER）：

| | 4K | 8K | 16K | 32K | 64K | 128K |
|---|---|---|---|---|---|---|
| GLM-4.7-Flash | 97.44 | 96.72 | 95.83 | 92.96 | 85.34 | 79.21 |
| + DSA warmup only | 97.51 | 96.54 | 95.40 | 90.09 | 84.05 | **71.35** |
| + DSA（150B 联训） | 96.77 | 96.25 | **+0.86** | **+0.49** | **+1.72** | 78.86 (−0.35) |

> 读法：只训 indexer 就已保住绝大部分能力，**退化集中在最长窗口**；联合训练把这个缺口几乎全补回来，中段还反超基线。

## 四、数据与 Mid-Training

> **概念速览**
> - **中训练（mid-training）**：预训练之后、后训练之前的过渡阶段，用更精、更专的数据**定向补强**——这里主要补两件事：**超长上下文**和 **agentic / 软件工程**。
> - **Lost-in-the-middle**：长文本中位于**中间段**的信息最容易被忽略的已知现象，合成长依赖数据就是为了对抗它。

**预训练数据**（27T）三条线：

- **Web**：新增一个基于句向量的 DCLM 分类器挖掘标准分类器之外的高质内容；用 **World Knowledge 分类器**（Wikipedia 条目 + LLM 标注优化）从中低质数据中蒸馏长尾知识。
- **Code**：刷新主流托管平台快照 + 更大规模含代码网页，**模糊去重后唯一 token +28%**；修正 Software Heritage 的 metadata 对齐问题；为 Scala / Swift / Lua 等低资源语言训专用分类器。
- **Math & Science**：改进网页抽取与 PDF 解析；LLM 打分只留最具教育价值的文档；长文档用 **chunk-and-aggregate 打分**提高准确率。**严格过滤合成 / AI 生成 / 模板化数据**。

**Mid-training**（1.55T）把上下文三段式拉长：

| 阶段 | token | 要点 |
|---|---|---|
| 32K | 1T | — |
| 128K | 500B | — |
| **200K** | 50B | 超长文档、多文件代码库；追加 MRCR-like 数据强化长多轮召回 |

软件工程数据：仍是 repo 级文件 + commit diff + issue + PR + 相关源文件拼成统一序列，但**放宽 repo 级筛选、收紧单 issue 级质量过滤**，得到约 **1000 万 issue–PR 对 / ~160B 唯一 token**，并为每对检索更多相关文件。

长上下文合成借鉴 NextLong / EntropyLong，用**交错打包高相似文本**构造长程依赖，缓解 lost-in-the-middle。

> 一个值得记的经验：**在 128K 阶段之后再加一段 200K mid-training，连 128K 窗口内的表现都变好了**。数据多样性的提升是单调收益。

## 五、训练基础设施：全是「省显存 / 填气泡」

> **概念速览**
> - **流水线并行（PP）**：把模型按层切成若干 **stage** 分布到不同 GPU，像流水线一样传递微批次。切不均时就有 GPU 干等——这段空转叫**气泡（bubble）**。
> - **激活（activation）**：前向算出、反向还要用的中间结果，是训练时的显存大头。对策有两种——**重算**与 **offload**。
> - **QAT（量化感知训练）**：训练时就模拟低比特（如 INT4）的舍入行为，让模型提前适应，避免事后量化掉点。
>
> 本节所有技巧只服务两个目标：**把显存峰值压下去**（才能塞下 744B）、**把气泡填满**（才能不浪费卡时）。相关并行基础可参阅[《Megatron-LM 分布式训练》系列](/blog/megatron-lm-01-overview/)。

**显存侧**

- **灵活的 MTP 放置**：MTP 横跨 embedding / transformer / output，显存远高于其他模块，造成 stage 失衡。把 MTP 输出层与主输出层**共置于最后一级并共享参数**，embedding 与 transformer 部分放前一级。
- **Pipeline ZeRO2 梯度分片**：每个 stage 只存 1/dp 的梯度；仅为**两个 stage** 保留完整累加 buffer 并做双缓冲——一个在累加时，另一个在同步，实测零额外同步开销。
- **Muon 分布式优化器零冗余通信**：只 all-gather 本 rank 拥有的参数分片，并与本地计算重叠，消掉瞬时显存尖峰。
- **Pipeline 激活 offload**：warmup 期前向远超反向，激活寿命被拉长；按**层粒度** offload 到 host 并在反向前回载，调度上避开 P2P 通信与 MoE token 路由的争抢，近零开销。
- **序列分块输出投影**：把序列切块、逐块独立算 projection + 交叉熵并及时释放激活，峰值显存随块数下降。

**并行侧**

- **延迟权重梯度计算**：把部分 weight grad 从关键路径挪走以减少气泡（Zero Bubble 思路），细粒度延迟 + 存储/通信重叠。
- **长序列训练**：workload-aware 序列重排、注意力计算动态再分配、把 DP ranks **柔性切分为不同大小的 CP 组**；QKV 用分层 all-to-all 重叠节点内/节点间通信。

**INT4 QAT**：在 SFT 阶段做量化感知训练，并自研量化 kernel 同时服务训练与离线权重量化，**保证训练与推理 bitwise 一致**。

## 六、后训练：顺序 RL + 最后一步「回收」

> **概念速览**
> - **On-policy vs off-policy**：用**当前**策略产出的数据训练当前策略叫 on-policy，最稳但慢；用**旧版本**策略产的数据训练叫 off-policy，快但有偏差，需要重要性采样和截断（clipping）来纠偏。异步训练天然是 off-policy，这是 6.4 节所有机制的由来。
> - **训推不一致（training–inference mismatch）**：生成用的推理引擎与计算梯度的训练引擎，数值实现不完全相同，同一串 token 算出的概率会有微小差异——在 RL 里会被放大成训练崩溃。
> - **灾难性遗忘**：按顺序优化多个目标时，后面的阶段会侵蚀前面阶段学到的能力。

```text
GLM-5 Base
  → SFT（202,752 ctx，三种 thinking 模态）
  → Reasoning RL（math / science / code / TIR 混合，二值结果奖励）
  → Agentic RL（coding / terminal / search，全异步解耦）
  → General RL（写作 / 文本处理 / 主客观问答 / 角色扮演 / 翻译；规则 + ORM + GRM 混合奖励，人写回答做风格锚）
  → On-Policy Cross-Stage Distillation（把前面阶段的能力找回来）
  → GLM-5
```

### 6.1 SFT：三种「思考模态」

- **Interleaved Thinking**：每次回复和每次工具调用之前都思考。
- **Preserved Thinking**：coding agent 场景下**跨多轮保留全部 thinking block**，复用已有推理而不是重新推导——减少信息丢失与前后不一致，适配长时序任务。
- **Turn-level Thinking**：会话内按轮开关思考，轻任务关掉省延迟/成本，复杂任务打开。

数据侧两个细节值得抄：

1. 数学与科学做**难度过滤，只留对 GLM-4.7 仍然困难的题**；
2. agent 轨迹中**错误片段保留但在 loss 中 mask 掉**——让模型学到「纠错行为」，又不强化错误动作。

### 6.2 Reasoning RL：GRPO + IcePop，且砍掉 KL

> **IcePop 一句话**：比较同一个 token 在**训练引擎**与**推理引擎**下算出的概率之比，凡偏离太远的 token 就**直接丢掉它的梯度**，只用训推一致的 token 更新策略——避免两个引擎间的数值与 MoE 路由差异在 RL 中被滚雪球放大。

显式区分**训练策略** $\pi^{\text{train}}$ 与**推理策略** $\pi^{\text{infer}}$，用 mismatch ratio

$$\rho_{i,t}=\frac{\pi^{\text{train}}_{\theta_{old}}(y_{i,t}\mid x,y_{i,<t})}{\pi^{\text{infer}}_{\theta_{old}}(y_{i,t}\mid x,y_{i,<t})}$$

作 `pop` 门控：$1/\beta \le \rho \le \beta$ 时保留，否则**该 token 梯度置零**。相比原始 IcePop，**移除 KL 正则项以加速提升**。超参 $\beta=2$、$\epsilon_{low}=0.2$、$\epsilon_{high}=0.28$，**完全 on-policy，group size 32，batch size 32**。

四域混合（数学 / 科学 / 代码 / 工具集成推理 TIR），比例大致均衡，**各域同步稳定上升**。难度过滤的判据很明确：**GLM-4.7 极少做对或持续失败，但更强的教师模型（GPT-5.2 xhigh、Gemini 3 Pro Preview）能做对**。

### 6.3 DSA 的 RL 踩坑记录（本文最实用的一段）

DSA 的 indexer 要 top-k 检索 KV 条目，**top-k 结果的训推一致性直接决定 RL 稳定性**。类比 MoE 的 routing replay，但 **indexer replay 不可行**——indexer 的 $k=2048$ 远大于 MoE 的 k，逐 token 存索引的存储与训推引擎间通信代价都不可接受。

实测结论：

- SGLang DSA Indexer 里**非确定性的 CUDA top-k**，以及 TileLang 实现，会让 RL **几步内剧烈崩塌，并伴随熵的陡降**；
- 朴素的 **`torch.topk` 虽然略慢但确定性**，输出一致、RL 收益显著 → 定为训练引擎默认算子；
- **RL 阶段默认冻结 indexer 参数**，加速并避免 indexer 自身的不稳定学习。

### 6.4 Agentic RL：异步是手段，稳定性是难点

目标函数是 group-wise 的均值基线形式，**只对模型生成的 token 计算损失，环境反馈不进 loss**：

$$\mathcal{L}(\theta)=\mathbb{E}_{x\sim D}\Big[\frac{1}{K}\sum_{i=1}^{K}\big(r(x,y_i)-\bar r(x)\big)\Big]$$

**异步设计**：训练引擎与推理引擎分置不同 GPU，推理引擎持续产轨迹，攒够阈值就发给训练引擎；每 $K$ 次梯度更新把新权重推回推理引擎。**每次权重同步后重置优化器**——因为 rollout 策略变了，优化问题本身已经变了。

**多任务 rollout 编排器**：每个任务把自己的 rollout 与奖励逻辑实现为独立微服务，注册到中央 orchestrator；orchestrator 控制各任务的 rollout 比例与生成速度，并把所有 agentic 任务的轨迹**统一成 message-list 表示**。支持 **>1k 并发 rollout**、任务采样比动态调整、细粒度进度监控。

**四个稳定性机制**：

| 机制 | 做法 | 解决什么 |
|---|---|---|
| **TITO Gateway** | 拦截所有生成请求，记录每条轨迹的 token ID 与 metadata，训练直接消费推理引擎产出的 token 流 | 避免 text-in-text-out 的重 tokenize 带来的边界/空白/特殊 token 错位，保住 action 级对应关系 |
| **直接双边重要性采样** | $r_t(\theta)=\pi_\theta/\pi_{\text{rollout}}$，**直接复用 rollout 期的 log-prob 当行为代理**，丢掉 $\pi_{\theta_{old}}$；落在 $[1-\epsilon_\ell, 1+\epsilon_h]$ 外的 token **整体从梯度中 mask** | 异步下单条轨迹横跨多个权重版本，精确追踪行为概率需维护大量历史 checkpoint，不可行 |
| **丢弃过期/噪声样本** | 记录每条响应涉及的权重版本序列 $(w_0,\dots,w_k)$，若 $w'-w_0>\tau$ 则丢弃；记录失败原因，**排除因环境崩溃而失败的样本**；组内有效样本过半则重复补齐，否则整组丢弃 | off-policy 漂移 + sandbox 不稳定带来的虚假奖励噪声 |
| **DP-aware 路由** | 一致性哈希把 rollout ID 固定映射到某个 DP rank（跨轮稳定），再叠加哈希空间上的轻量动态均衡 | 多轮 agent 请求共享长前缀，跨 rank 会 cache miss；固定亲和后 **prefill 成本只与增量 token 成正比，而非总上下文长度** |

### 6.5 slime 侧的尾延迟工程

RL rollout 的优化目标**不是吞吐而是端到端延迟**，由每步最慢的那条轨迹决定。

- **无排队服务**：多节点部署（如 8 节点 EP64 + DP64）提供足量分布式 KV cache；MLA 用 DP-attention 避免跨 rank 拷 KV。
- **FP8 rollout + MTP**：MTP 在 RL 典型的**小 batch 解码**区间收益被放大，而尾延迟恰由小 BS 的长尾样本（罕见长上下文、复杂多轮推理、重工具调用）造成——**正好打在尾部**。
- **PD 分离**：多轮场景长前缀 prefill 频繁，在 DP-attention 下与 decode 混跑会严重互扰（一次重 prefill 打断正在进行的 decode）；prefill / decode 各用专属资源后尾延迟显著改善。
- **心跳容错**：rollout server 周期性心跳，不健康的直接终止并从推理 router 注销，重试自动绕开故障/降级节点。

### 6.6 General RL：三维目标 + 三类奖励

目标分解为三个递进维度：

| 维度 | 管什么 | 具体内容 |
|---|---|---|
| **基础正确性** | 把错误率压到「可用」基线 | 指令遵循失败、逻辑不一致、事实错误、知识幻觉、语言不流畅 |
| **情商** | 超出正确性的用户体验 | 共情、有洞察、风格贴近真实的人类表达 |
| **任务专项质量** | 从「正确」抬到「优秀」 | **写作、文本处理、主客观问答、角色扮演、翻译**五类高频任务 |

基础正确性被当作**一切后续优化的前置条件**：含事实错误或误解意图的回答，再精致也是在误导用户。而任务专项质量这一维直接导出了混合奖励的必要性——**五类任务各自需要形态完全不同的奖励信号**（翻译可对照参考译文、角色扮演只能靠评判、文本处理部分可规则化），没有任何单一奖励能同时覆盖。

| 信号 | 是什么 | 优点 | 缺点 |
|---|---|---|---|
| **规则奖励** | 人写死的判定逻辑：格式/长度校验、答案精确匹配、单元测试通过与否 | 精确、可解释 | 只覆盖能被确定性规则表达的部分 |
| **ORM**（结果奖励模型） | 判别式打分器，输入「问题+回答」直接输出一个标量分，由人类偏好数据训得 | 低方差、训练效率高 | 只看结果不讲理由，**更易被 reward hacking** |
| **GRM**（生成式奖励模型） | 用 LLM 当评委，按 rubric 先写评述再给分 | 要「讲理由」，对投机取巧更鲁棒 | 方差与成本更高 |

> 一句话概括互补关系：**规则保精度，ORM 保效率，GRM 保鲁棒**——单用任何一个都会塌，混合才稳。rubric 的写法细节见[《Rubrics 用于 LLM 评测与 RL》](/blog/rubrics-for-llm-eval-and-rl/)。

**人在环中的风格对齐**：显式引入高质量**人类撰写的回答**作为风格与质量锚点。动机是纯模型生成的优化会收敛到可辨识的「模型腔」——冗长、套路化、缺少细腻处。

### 6.7 On-Policy 跨阶段蒸馏：顺序 RL 的「回收站」

多阶段顺序优化必然累积遗忘。GLM-5 把**在线策略蒸馏放在最后一步**：以前序各阶段的最终 checkpoint 为教师，prompt 从各教师的 RL 训练集按比例混采，把 advantage 换成

$$\hat A_{i,t}=\text{sg}\Big[\log \frac{\pi^{\text{infer}}_{\theta_{teacher}}(y_{i,t}\mid x,y_{i,<t})}{\pi^{\text{train}}_{\theta}(y_{i,t}\mid x,y_{i,<t})}\Big]$$

因为 advantage 直接由「与教师的差距」给出，**不再需要每个 prompt 维持一大组采样来估计 advantage** → group size 设为 **1**、batch size 开到 **1024**，数据吞吐大幅提升。

## 七、环境规模化：Agentic 能力的真正瓶颈

> **概念速览**
> - **可验证环境（verifiable environment）**：一个能真实跑起来、并能**自动判对错**的沙箱（通常是 Docker 容器 + 测试脚本）。Agent RL 的奖励就来自这里——没有环境，就没有奖励信号。
> - **F2P / P2P 测试**：**Fail-to-Pass** 是修复前失败、修复后必须通过的测试；**Pass-to-Pass** 是修复前后都必须通过的测试。两者合起来才是一次合格的验收。
> - **Reward hacking（奖励作弊）**：模型发现了钻奖励函数空子的捷径，分数上去了但实际质量没有——7.5 节有两个非常直观的实例。

### 7.1 SWE 环境：>10k 个可验证实例

真实 issue–PR 对经规则 + LLM 双重过滤，按**缺陷修复 / 功能实现 / 重构 / 其他**分类，并补足任务要求使实现与 test patch 一致。基于 **RepoLaunch** 的流水线自动分析仓库安装与依赖、构建可执行环境、生成测试命令，再用 LLM 产出**语言感知的日志解析函数**，从测试输出中抽取 **F2P / P2P** 用例。

规模：**>10k 可验证环境，覆盖数千仓库、9 种语言**（Python、Java、Go、C、C++、JavaScript、TypeScript、PHP、Ruby）。

### 7.2 终端环境：两条合成线

- **种子驱动**：真实 SWE 与 computer-use 场景采种子 → LLM 头脑风暴出大批任务草稿 → 构造 agent 实例化为 **Harbor 格式**（结构化描述 + Docker 环境 + 测试脚本）→ refine agent 按人工 rubric 迭代打磨，确保镜像可靠构建、测试与规格一致、**环境对作弊与捷径鲁棒**。产出数千环境，**Docker 构建成功率 >90%**。
- **网页语料驱动**：闭环设计，**构造 agent 兼任第一道评审**。质量分类器筛代码相关网页 → 按主题与难度分层采样 → 给 coding agent 投喂 Harbor 构造规范 + 源网页，要求它既合成任务、又对自己的产出跑 Harbor 校验脚本；校验失败则自行诊断修订，**只有通过自验证闭环的任务才入库**。

### 7.3 搜索任务：Web Knowledge Graph

目标是合成**多跳 QA**——每道题都必须靠跨多个网页聚合证据、分步推理才能答出。整条流水线分建图、出题、过滤三段。

**① 建图：用 agent 自己的轨迹做种子**

起点不是通用爬虫，而是**早期搜索 agent 实际走过的轨迹**：收集并去重其中遭遇过的全部 URL，保留**超 200 万高信息量网页**，覆盖多个领域。这是一个自举闭环——页面分布天然落在「agent 真的会访问到」的区域上，而不是互联网的平均分布。

LLM 对每个页面做**语义解析**三件事：实体识别、噪声过滤、结构化信息抽取。

图不是一次建完就冻结：新页面持续并入，并用**下游验证信号反向精炼**，手段有四类——**实体对齐**、**属性归一化**、**关系合并**、**语义一致性修正**。也就是说，出题与验证环节发现的矛盾会回流去修图。

**② 出题：子图 → 隐式关系链**

| 环节 | 做法 | 为什么 |
|---|---|---|
| 种子选取 | 只采**低频到中频实体** | 高频实体（名人、大事件）靠参数记忆就能答，构不成「必须搜索」的题 |
| 邻域扩展 | 围绕种子扩**多跳邻域**形成完整子图，同时**控制扩展以减少子图间重叠** | 重叠过多会让题目同质化，RL 的 prompt 多样性坍塌 |
| 问题生成 | 用面向**高难度、跨领域推理**的 prompt，把子图转成**隐式编码多实体关系链**的问题 | 「隐式」是关键：题面不暴露中间实体，必须一跳跳推出来，否则退化成单跳检索 |

**③ 过滤：前两级设难度下界，第三级保标签可靠**

| 级 | 判据 | 卡掉什么 |
|---|---|---|
| 1 | 无工具推理模型 **8 次独立尝试中只要对过 1 次** → 删 | 靠**参数记忆**就能答的题。等价于要求 pass@8 = 0，门槛极严 |
| 2 | 早期 agent 用基础 search / browse / 计算**在几步内**能解 → 删 | 靠**浅层检索**就能答的题 |
| 3 | 验证 agent 做**双向验证** | 标签本身不可靠的题 |

第三级值得展开：从**阶段 2 的搜索轨迹**里收集**候选答案**，然后对「候选答案」与「标注答案」**各自独立**校验问答一致性，三类样本一律拒绝——**答案不唯一、证据相互矛盾、标注错误**。

> 「双向」的含义是：不只问「标注的答案对不对」，还要反过来问「**是不是存在另一个同样满足全部约束的答案**」。这恰是多跳合成题最容易翻车的地方——知识图谱里一条关系链看似唯一确定，现实世界中却可能有第二个实体同时满足所有条件，于是题目变成无解的噪声奖励。

**回报**：BrowseComp **62.0**（全场最高，Claude Opus 4.5 仅 37.0）、BrowseComp-ZH **72.7**（开源最高）。叠加下一节的上下文管理后 BrowseComp 达 **75.9**。

### 7.4 推理期上下文管理：BrowseComp 从 55.3 到 75.9

先说一个评测洁癖：BrowseComp 对 **judge prompt 与 judge model 都很敏感，开源 judge 会引入系统性偏差**。本文统一采用 **OpenAI 官方评测 prompt + o3-mini 作 judge**，理由是 case study 显示这组配置与人工标注最吻合。

观察：**超长上下文（>100k token）下准确率显著退化**。

- **Keep-recent-k**：轨迹 $(q, r_1,a_1,o_1,\dots,r_n,a_n,o_n)$（4 个工具：search / open / find / python），只**折叠最近 k 轮以外的 observation**（替换为 "Tool result is omitted to save tokens"），推理 $r_i$ 与动作 $a_i$ 保留。$k=5$：**55.3% → 62.0%**。有趣的是，换 k 值或改成「上下文到阈值才触发」，**结果一样**。
- **分层上下文管理（HCM）**：在 keep-recent 之上，总上下文超过 $T$ 就**丢弃整个工具调用历史、重开干净上下文**，同时继续 keep-recent。参数搜索得 $T=32\text{k}$。在各算力预算下都一致优于单用 Discard-all，**最终 75.9，超过所有配备上下文管理的开源模型**。

> 机制很朴素：上下文腾出来 → 同样预算内能多走几步 → 分数上去。**长时序 agent 的瓶颈经常不是「能不能想」，而是「还有没有地方想」。** 上下文压缩在 agent 框架侧的通用做法，见[《Harness Engineering 综述》](/blog/harness-engineering-survey-2026/)与[《OpenClaw 源码（二）：Agent Loop 与上下文压缩》](/blog/openclaw-02-agent-loop/)。

### 7.5 Slide 生成：三级奖励与 reward hacking 实录

HTML 幻灯片生成的奖励被切成三层：

| 层级 | 观测对象 | 内容 |
|---|---|---|
| L1 静态标记属性 | 生成的 HTML 声明 | 定位、间距、颜色、排版、饱和度等；规则保证语法可解析，并把设计空间约束到表达力/结构清晰/视觉和谐/可读性更优的子空间；含**幻觉图片与重复图片检测** |
| L2 运行时渲染属性 | 渲染中的 DOM 节点 | 元素宽高、bounding box 等几何布局指标；自建**分布式渲染服务**高吞吐抽取 |
| L3 视觉感知特征 | 渲染后的画面 | 如异常留白模式检测，提升构图平衡与美观 |

训练中抓到两类典型 **reward hacking**：**把超长内容硬截断藏起来**（1280×1015 被裁成 1280×720）、**疯狂加间距撑布局**。应对不是改奖励权重，而是**修渲染器实现、堵掉可利用的漏洞**——让奖励真正奖励美观，而不是奖励对几何指标的表面合规。

其余训练技巧：动态采样概率性丢弃结构平凡样本；token 级策略梯度损失；**把同一样本的不同 rollout 结果分散到多个 batch** 以降低优化偏差。拒绝采样阶段把 RL 奖励函数复用为数据过滤器，Best-of-N 选优；再用**掩码式修正**——只 mask 掉轨迹中少数缺陷页面而非丢弃整条轨迹。

效果：严格符合 **16:9 的页面占比 40% → 92%**，溢出大幅减少；相对 GLM-4.5 的人工评测胜率——内容质量 60%、布局合理性 57.5%、视觉美观 65%、**整体 67.5%**。

## 八、国产芯片全栈适配

> **概念速览**
> - **量化记法 WxAy**：权重 x 位、激活 y 位。**W8A8** 即权重和激活都是 INT8，**W4A8** 即权重压到 INT4、激活保持 INT8。
> - **离群值（outlier）**：少数数值特别大的权重/激活，是低比特量化掉点的主因，需要专门算法（如 QuaRot 的旋转变换）去抑制。
> - **算子融合**：把多个小算子合并成一个 kernel 一次算完，减少反复读写显存——对访存受限场景提速明显。

**第一天起**就完成七个主流国产平台的全栈适配：**华为昇腾、摩尔线程、海光、寒武纪、昆仑芯、沐曦、燧原**。以昇腾 Atlas 为例，三根支柱：

- **W4A8 混合精度量化**：为把 744B 塞进**单台 Atlas 800T A3**，用 msModelSlim 做分层精度——标准 Attention 与 MLP 走 **W8A8 (INT8)**，**MoE 专家压到 W4A8 (INT4)**；配合 QuaRot 抑制离群值、Flex_AWQ_SSZ 做缩放标定维持低比特稳定性。
- **高性能融合算子**：**Lightning Indexer**（score 计算 + ReLU + TopK 融进单 kernel，让 NPU 用计算掩盖访存）、**Sparse FlashAttention**（KV cache 的 TopK 选择与稀疏注意力计算并行）、**MLAPO**（把 13 个小预处理算子融成一个「超级算子」，并行利用 Vector 与 Cube 单元）。
- **推理引擎专项**：vLLM-Ascend 的**异步调度**、Radix Cache / Prefix Cache（KV 扩展到系统内存）、**Attention DP + MoE EP 混合并行 + FlashComm**、MTP 提升单步计算密度。

结论：**单台国产节点达到双 GPU 国际集群的可比性能，长序列场景部署成本降低 50%**。

## 九、评测

> **概念速览**
> - **BSR / ISR / CSR**（CC-Bench-V2 前端三指标）：**Build Success Rate** 项目能否成功构建运行；**Check-item Success Rate** 所有检查项的细粒度完成率；**Instance Success Rate** 一个任务的检查项**全部**通过的比例。CSR 高而 ISR 低，意味着「大部分要求都做到了，但很少有任务被完整做完」。
> - **Agent-as-a-Judge**：用一个配了浏览器工具的 agent 代替人类评审，去真实点击页面、截图、读终端，再逐项判定通过与否。
> - **数据污染与去污染**：静态公开的 benchmark 可能已混进训练数据，分数虚高。SWE-rebench 这类持续挖掘**新鲜**题目的榜单就是为此而设。

### 9.2 CC-Bench-V2：Agent-as-a-Judge

内部评测升级为 **CC-Bench-V2，完全去掉人工标注**，用 Claude Code 等 agent harness + 单元测试 + Agent-as-a-Judge 全自动跑。

前端的难点在于**正确性本质是视觉与交互的**——bug 往往只在用户点按钮、缩窗口时才暴露，静态分析与固定测试套件都不够。因此每个项目先在 Docker 里构建，构建成功的交给 **Judge Agent（Claude Code + Claude Sonnet 4.5 + Playwright MCP）** 闭环验收：读源码 → 操作实时 UI（点击、键入、截图）→ 查终端输出 → 给每个 check-item 判 pass/fail。

可靠性验证做得很扎实：**130 个 check-item 上与人类专家一致率 94%**（分歧集中在主观视觉质量而非功能规格）；对 8 个前沿模型同时跑自动框架与人工专家，**排序 Spearman 相关 85.7%**。

| 类别 | 任务 | 指标 | GLM-5 | GLM-4.7 | Claude Opus 4.5 |
|---|---|---|---|---|---|
| 前端 | HTML | ISR / CSR | 38.9 / 76.3 | 35.4 / 64.9 | **52.2 / 82.2** |
| | React | ISR / CSR | 34.6 / **71.0** | 17.2 / 49.4 | **39.7** / 70.7 |
| | Vue | ISR / CSR | 32.7 / **77.1** | 24.5 / 53.8 | **46.9** / 74.3 |

| | Next.js | BSR | **95.0** | 70.0 | 80.0 |
| 后端 | 85 任务 / 6 语言 | Pass@1 | 25.8 | 19.6 | **26.9** |
| 长时序 | 大仓探索 | Pass@1 | **65.6** | 47.8 | 64.5 |
| | 链式任务 | Pass@1 | 52.3 | 43.0 | **61.6** |

三条诊断：

1. **前端：CSR 追平、ISR 仍差**。GLM-5 能满足大多数**单条**需求，但把**整个任务端到端做全**仍不及 Claude Opus 4.5。
2. **大仓探索反超 Opus 4.5**。题目刻意反关键词搜索：问题只用业务语义描述、绝不提文件名/类名/函数名，需要 1–2 跳逻辑推理，目标文件至少三层目录深、名字晦涩、功能唯一、不在主功能面上。论文的解读是——**repo 探索靠的不是代码生成能力，而是策略性搜索**（目录级推理 + 语义联想迭代收窄文件空间），这正是 agentic 工具使用轨迹训练的直接产物。
3. **链式任务仍有显著差距**。构造方式：筛含测试、3–15 个 commit、线性历史的 merged PR → LLM 给相邻 commit 打语义相关性、**动态规划切出最优任务组** → 累积 diff 三分为 golden patch / test patch / auto-apply patch → 自动分类并按「错误消除 / 关键路径准确性 / 测试通过」三轴评估。执行时**状态递归累积**：完成第 k 个任务即提交，再应用第 k+1 的 auto-apply patch；评测累积应用 1..k 的 test patch 后跑全量测试，**同时抓当前失败与对早期任务的回归**。差距原因直白：**错误沿链累积，某一步的次优修改会静默破坏后续任务的测试**。

## 十、彩蛋：Pony Alpha

> **概念速览**：**OpenRouter** 是一个聚合各家大模型 API 的网关平台，厂商常在此以**代号匿名**上线新模型做盲测——用户不知道是谁家的，反馈因此不受品牌与立场影响。

GLM-5 曾以匿名模型 **"Pony Alpha"** 在 OpenRouter 上线。数日内在复杂编码、agentic workflow 与角色扮演上引发关注，社区猜测版本分布为：**25% 猜 Claude Sonnet 5、20% 猜 DeepSeek、10% 猜 Grok，其余才猜 GLM-5**。

团队的自我总结分两半：匿名发布「剥掉品牌名、让能力自己说话」，也**让反馈绕过了地缘偏见**；但同时强调要保持务实——**开源权重与绝对专有前沿之间的差距在收窄，但竞赛远未结束**。

## 十一、可带走的 8 条

1. **注意力效率不是免费的，但 DSA 接近免费**。搜索式 SWA 和线性注意力都在细粒度检索上留下不可消除的缺口；DSA 靠「token 级稀疏但不丢长程依赖」做到构造上无损，因此敢上**所有层**。
2. **换注意力机制可以很便宜**：20B token 的稀疏适配就把 DSA 拉到 MLA 水平（DeepSeek-V3.2 用了 943.7B）。
3. **优化器配方会决定架构选型**。MLA 在 Muon 下打不过 GQA-8，但 **Muon Split**（按头独立正交化）把它救回来，还顺带让 attention logits 不需要 clipping。
4. **RL 对非确定性零容忍**。`torch.topk` 慢一点但确定，非确定性 top-k 几步内就让 DSA 模型熵崩。异步 RL 的另一半答案叫 **TITO**——不要让文本往返重新 tokenize。
5. **异步换吞吐，必须配套四件套**：复用 rollout log-prob 的双边 clipping、按权重版本丢弃过期样本、剔除环境崩溃样本（并补齐/丢弃整组）、每次权重同步后重置优化器。
6. **长时序 agent 的瓶颈常是上下文预算**。Keep-recent-5 折叠旧 observation：BrowseComp 55.3→62.0；再叠 32k 阈值的 Discard-all：→75.9。
7. **堵漏洞优于调权重**。Slide RL 里对付「硬截断」和「疯狂加间距」，靠的是修渲染器而不是改奖励系数——**奖励可被 hack 时，先修环境**。
8. **评测要自己造，而且要能被审计**。Agent-as-a-Judge 与人类 94% 点一致、排序 85.7% 相关；同时主动报告 SWE-rebench 上只有 42.1% 与链式任务 52.3 vs 61.6 的差距——**自建 benchmark 的可信度来自它敢揭示自己的短板**。

## 小结

把 GLM-5 压成一句话：**Agentic engineering 的三个瓶颈分别落在推理成本、RL 吞吐、环境供给上，而不是模型结构的某个巧思上。**

三条最该记住的：

- **省注意力要选「按内容选信息」而不是「按位置/压缩丢信息」**，否则细粒度检索上的缺口消不掉。
- **异步 RL 的收益来自填气泡，代价是 off-policy 与环境噪声**，四件稳定性机制缺一不可；而一切的前提是 token-in/token-out。
- **环境就是奖励**：>10k 可验证 SWE 环境、数千终端环境、知识图谱合成的多跳搜索题，才是 agentic 能力的真实来源。
