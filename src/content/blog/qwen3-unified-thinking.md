> **本文解决一个问题**：2025 年初的常态是**两个模型**——一个管对话、一个管推理，用户得手动切换；而每个尺寸的小模型都要把完整后训练重跑一遍，算力成本线性叠加。
>
> Qwen3 的答案是**两件合并**：把两种模态合并进一个模型（`/think` 与 `/no_think`，并进一步暴露 thinking budget），把八次后训练合并成「旗舰跑一次四阶段 + 其余蒸馏」。本文按预训练、后训练、蒸馏、评测、代价五段拆解，重点放在三件可迁移的事：冷启动为什么要刻意克制、3,995 条 RL 数据凭什么顶用、以及 on-policy 蒸馏为什么在小模型上全面优于 RL。
>
> 论文：*Qwen3 Technical Report*（Qwen Team，阿里巴巴，arXiv:2505.09388v1，2025-05-15）。模型：6 个 dense（0.6B/1.7B/4B/8B/14B/32B）+ 2 个 MoE（30B-A3B、235B-A22B），全系 **Apache 2.0**。

## 一、一句话定位

> **概念速览**
> - **思考模式 / 非思考模式**：前者先生成一段长链思考（`<think>...</think>`）再作答，用于数学、代码等多步推理；后者直接作答，用于闲聊、翻译等低延迟场景。
> - **MoE（混合专家）**：前馈层拆成许多「专家」，每个 token 只路由到少数几个。总参数可以很大，但单次前向只算一小部分（激活参数）。「235B-A22B」即 235B 总参 / 22B 激活。
> - **Thinking budget（思考预算）**：给思考过程设 token 上限，到了就强制收尾出答案——把「推理深度」变成一个**可调旋钮**而不是固定属性。

Qwen3 的全部设计围绕两件合并：

1. **把两个模型合并成一个模式**。用 `/think` 与 `/no_think` 标记在同一模型内切换，并进一步暴露 thinking budget，让用户按任务复杂度分配推理算力。
2. **把八次后训练合并成一次**。旗舰模型跑完整的四阶段后训练，其余 6 个轻量模型直接从旗舰**蒸馏**，GPU 小时只要 1/10。

交付结果（旗舰 Qwen3-235B-A22B）：

- **思考模式**：AIME'24 **85.7**、AIME'25 **81.5**、LiveCodeBench v5 **70.7**、CodeForces **2056（98.2%）**、BFCL v3 **70.8**。以 **60% 激活参数、35% 总参数**在 23 项中的 **17 项**胜过 DeepSeek-R1。
- **非思考模式**：23 项中 **18 项**胜过 GPT-4o-2024-11-20，Arena-Hard **96.1**（GPT-4o 85.3）。
- **多语言**：从 Qwen2.5 的 29 种扩到 **119 种语言与方言**。

## 二、架构：做减法，不做加法

> **概念速览**
> - **GQA（分组查询注意力）**：多个 Q 头共用一组 KV 头，省显存与带宽。表中「32 / 8」即 4 个 Q 头共享一组 KV。
> - **QK-Norm**：对 Query/Key 做归一化，把 attention logits 数值范围压稳，防训练发散。
> - **Tie embedding（权重绑定）**：输入词嵌入与输出投影共用一份权重，小模型里能省下可观比例的参数。
> - **细粒度专家切分 / 共享专家**：前者把专家切得更小更多以提升组合灵活度；后者指「所有 token 都必走」的常驻专家，用于承载通用知识。
> - **全局批次负载均衡损失**：在**整个全局 batch** 而非单个 micro-batch 上做专家负载均衡，约束更松，因而允许专家**真正分化**出领域倾向。

Qwen3 相对 Qwen2.5 的架构改动几乎全是**删除**：

| 变化 | 内容 |
|---|---|
| 删 | **QKV-bias**（Qwen2 引入，此处移除） |
| 加 | **QK-Norm**（换取训练稳定性） |
| 删 | **共享专家**（Qwen2.5-MoE 有，Qwen3-MoE 没有） |
| 换 | 负载均衡损失 → **全局批次版本**，目的明确写为「鼓励专家特化」 |

其余沿用成熟配置：GQA、SwiGLU、RoPE、RMSNorm + pre-norm；tokenizer 为 BBPE，词表 **151,669**。

**Dense 系列**

| 模型 | 层数 | Q / KV 头 | Tie Embedding | 上下文 |
|---|---|---|---|---|
| Qwen3-0.6B | 28 | 16 / 8 | Yes | 32K |
| Qwen3-1.7B | 28 | 16 / 8 | Yes | 32K |
| Qwen3-4B | 36 | 32 / 8 | Yes | 128K |
| Qwen3-8B | 36 | 32 / 8 | No | 128K |
| Qwen3-14B | 40 | 40 / 8 | No | 128K |
| Qwen3-32B | 64 | 64 / 8 | No | 128K |

**MoE 系列**

| 模型 | 层数 | Q / KV 头 | 专家（总 / 激活） | 上下文 |
|---|---|---|---|---|
| Qwen3-30B-A3B | 48 | 32 / 4 | 128 / 8 | 128K |
| Qwen3-235B-A22B | 94 | 64 / 4 | 128 / 8 | 128K |

> 读法：两个 MoE **共用同一套专家配置（128/8）**，只靠层数与头数区分规模——配置被当作可复制的「标准件」，而非每个模型重新搜一次。

> 想看这套 MoE 在真实训练脚本里长什么样、与 DeepSeek-V3 的并行哲学差在哪，可以对照[《DeepSeek-V3 实战解读》](/blog/deepseek-v3-training-explained/)第十节，以及[《Qwen3-235B-A22B 64 卡全参 SFT 实战》](/blog/qwen3-235b-sft-roleplay/)。

## 三、预训练：36T token 与「用模型造数据」的飞轮

> **概念速览**
> - **合成数据飞轮**：用上一代模型批量生产下一代的训练语料。Qwen3 的做法极其直白——**Qwen2.5-VL** 做 PDF OCR、**Qwen2.5** 做文本精炼、**Qwen2.5-Math / Coder** 合成数学与代码语料。
> - **实例级 vs 域级数据配比**：以往工作在「数据源/领域」粒度上调配比（多少网页、多少代码）；Qwen3 给 **30T+ token 逐条打标**（教育价值、领域、学科、安全性），在**单条样本粒度**上用小代理模型做消融来定配比。
> - **ABF / YARN / DCA**：三种长上下文技术。ABF 调大 RoPE 底频以容纳更长位置；YARN 与 DCA 在**推理时**外推，论文用它们把序列承载能力再放大 4 倍。

### 3.1 数据构造的三条产线

| 产线 | 做法 |
|---|---|
| **PDF 抽取** | Qwen2.5-VL 对海量 PDF 类文档做文字识别 → Qwen2.5 精炼质量，两步净增**万亿级**高质量 token |
| **领域合成** | Qwen2.5 / Math / Coder 合成教材、问答、指令、代码片段，覆盖数十个领域，规模同样**万亿级** |
| **多语言扩展** | 新增语料把支持语言从 **29 → 119** |

配比上，Qwen3 建了一套**多语言数据标注系统**，对 30T+ token 在教育价值、领域、学科、安全多个维度打标，再用细粒度标签在**小代理模型**上大规模消融，最终在**实例级**优化混合比例。

### 3.2 三阶段：30T → +5T → 长上下文

| 阶段 | 内容 | 规模 | 序列长度 |
|---|---|---|---|
| **S1 通用** | 119 种语言的通用语料，打语言与世界知识底子 | **>30T** | 4,096 |
| **S2 推理** | 上调 STEM / 代码 / 推理 / 合成数据占比，**同时加速学习率衰减** | **~5T**（更高质） | 4,096 |
| **S3 长上下文** | 高质量长文；其中 **75% 长度在 16K–32K，25% 在 4K–16K** | 数千亿 | **32,768** |

S3 的三件事：RoPE 底频 **10,000 → 1,000,000**（ABF）；引入 **YARN + DCA**，推理期再获 **4 倍**长度能力。

另外，三个阶段的最优学习率与 batch size 不是手调的，而是**各自拟合 scaling law 预测**出来的。

> 值得注意的是 S2 的「**加速学习率衰减**」：高质量推理数据被放在学习率快速下降的窗口里，等价于让模型在「最听话」的阶段集中吸收最想要的分布。

## 四、Base 模型评测：一代顶上一档

> **概念速览**
> - **Base（基座）模型**：只做完预训练、未经指令微调的裸模型，用 few-shot 测。它反映数据与架构的真实上限，不受对齐风格影响。
> - 评测覆盖 **15 个 benchmark**，分通用、数学与 STEM、代码、多语言四类。

**三条结论**：

1. **对 DeepSeek-V3-Base：15 项赢 14 项**，而总参只有 1/3、激活只有 2/3。唯一输的是 INCLUDE（区域性知识）。
2. **MoE 的参数效率**：同数据下 Qwen3-MoE 用 **1/5 激活参数**即可追平 Qwen3-dense；用 **1/10 激活参数**即可追平 Qwen2.5-dense。
3. **dense 整体上移一档**：Qwen3-1.7B/4B/8B/14B/32B ≈ Qwen2.5-3B/7B/14B/32B/72B，在 STEM、代码、推理上甚至更强。典型如 Qwen3-32B-Base 以**不到一半参数**在 15 项中赢 Qwen2.5-72B-Base **10 项**（MMLU-Pro 65.54 vs 58.07，MultiPL-E 67.06 vs 58.70）。

## 五、后训练四阶段：先把思考练出来，再把不思考装回去

> **概念速览**
> - **Long-CoT 冷启动**：用少量高质量长思维链数据做 SFT，目的不是提分，而是**给 RL 一个会生成长推理的起点**。
> - **GRPO**：省掉价值网络的 RL 算法——对同一问题采样一组答案，用组内均分当基线，高于均值的鼓励、低于的抑制。
> - **熵控制**：策略分布的「不确定度」。熵掉太快＝过早收敛不再探索，熵涨太猛＝发散。把熵约束为**稳步上升或保持平稳**是训练稳定的关键抓手。
> - **拒绝采样**：从模型大量采样，只保留通过校验的，当作 SFT 数据。

整条流水线：

```text
Qwen3 Base
  → Stage 1  Long-CoT Cold Start      （SFT，建立推理范式）
  → Stage 2  Reasoning RL             （GRPO，冲推理上限）
  → Stage 3  Thinking Mode Fusion     （继续 SFT，把 non-thinking 融回来）
  → Stage 4  General RL               （20+ 任务，补通用性与稳定性）
  → Qwen3 旗舰（235B-A22B / 32B）
       ↓ 强到弱蒸馏
  → 0.6B / 1.7B / 4B / 8B / 14B / 30B-A3B
```

**前两阶段造「会思考」，后两阶段装「能不思考」**——顺序不可颠倒，因为非思考能力是在一个已具备推理能力的模型上做 SFT 叠加的。

### 5.1 Stage 1：冷启动的全部重点是「筛」

数据覆盖数学、代码、逻辑推理、通用 STEM，每题配**可验证的参考答案或测试用例**。两轮过滤：

**Query 过滤**（用 Qwen2.5-72B-Instruct）

- 删掉不易验证的（含多个子问题、要求泛化文本生成）；
- 删掉**不用 CoT 也能答对**的——防止模型学会「表面猜测」；
- 标注领域，维持分布均衡。

**Response 过滤**（用 QwQ-32B 对每题生成 N 个候选；QwQ 持续失败的题交人工判定）。对 Pass@N > 0 的题，再删掉：① 最终答案错；② 大量重复；③ 明显是猜而无充分推理；④ **思考内容与总结内容不一致**；⑤ 语言混杂或风格突变；⑥ 疑似与验证集过于相似。

> **本阶段的目标被明确写为「不要追求推理性能」**：样本数与训练步数都应**尽量少**，只植入基础推理范式，避免压缩后续 RL 的提升空间。这是一条反直觉但极重要的工程纪律。

### 5.2 Stage 2：3,995 条数据，170 步，AIME 70.1 → 85.1

query-verifier 对的四条准入标准：**①冷启动未用过 ②对冷启动模型是可学的 ③尽可能难 ④覆盖广泛子领域**。最终只收了 **3,995 条**，用 GRPO 训练。

训练配置的三条经验：**大 batch size**、**每个 query 高 rollout 数**、**off-policy 训练提样本效率**；稳定性靠**控制熵稳步上升或保持平稳**来平衡探索与利用。

结果：Qwen3-235B-A22B 的 AIME'24 在**单次 RL run、170 步、零手工干预超参**的条件下从 **70.1 → 85.1**。

> 这是全文信息密度最高的一个数字。它说明在 RL 阶段，**数据质量与课程设计的权重远高于数据规模**——四千条精选题的边际收益，超过很多工作里几十万条的混合池。GRPO 的实现细节可对照[《verl 源码剖析（四）：PPO/GRPO 核心》](/blog/verl-04-ppo-grpo-core/)。

### 5.3 Stage 3：Thinking Mode Fusion（融合，而非开关）

目标是把 non-thinking 能力装回 Stage 2 的推理模型。手段是**继续 SFT** + **chat template 设计**。

**数据构造的关键一招**：thinking 数据不是外部来的，而是**用 Stage 2 模型自己对 Stage 1 的 query 做拒绝采样**生成——这样 SFT 就不会把 Stage 2 的推理能力洗掉。non-thinking 数据则广覆盖代码、数学、指令跟随、多语言、创意写作、问答、角色扮演，并用**自动生成的检查清单（checklist）**评估回答质量；为提升低资源语言，**特意提高翻译任务占比**。

**模板设计**：

| 思考模式 | 非思考模式 |
|---|---|
| `<\|im_start\|>user`<br>`{query} /think<\|im_end\|>`<br>`<\|im_start\|>assistant`<br>`<think>`<br>`{thinking content}`<br>`</think>`<br>`{response}<\|im_end\|>` | `<\|im_start\|>user`<br>`{query} /no_think<\|im_end\|>`<br>`<\|im_start\|>assistant`<br>`<think>`<br>`</think>`<br>`{response}<\|im_end\|>` |

三个细节：

- **非思考模式保留一个空的 `<think></think>` 块**。内部格式因此完全一致，开发者可以直接在模板里拼一个空 think 块来强制禁用思考。
- **默认即思考模式**，所以额外加入了「用户 query 不带 `/think` 标记」的思考样本。
- **多轮对话中随机插入多个标记**，模型被训练为**遵循最后一个遇到的标记**。

**Thinking Budget 是涌现的，不是训练出来的。** 一旦模型同时掌握两种模式，它自然获得了「基于不完整思考作答」的能力。于是实现方式非常朴素——思考长度到阈值时**手动截断**并插入一句：

```text
Considering the limited time by the user, I have to give the solution
based on the thinking directly now.
</think>
```

模型随即基于已有推理给出最终答案。论文明确指出：**这一能力未被显式训练，是 Thinking Mode Fusion 的副产品。**

### 5.4 Stage 4：General RL 的 20+ 任务与三类奖励

覆盖五类核心能力：

| 能力 | 内容 |
|---|---|
| **指令跟随** | 内容、格式、长度、结构化输出等要求 |
| **格式跟随** | 正确响应 `/think`、`/no_think`，一致使用 `<think>` 分隔符 |
| **偏好对齐** | 开放式问题的有用性、参与感与文风 |
| **Agent 能力** | 通过指定接口调用工具；RL rollout 中允许**完整多轮交互 + 真实环境执行反馈** |
| **专项场景** | 如 RAG：用奖励信号引导模型贴合上下文作答，压低幻觉 |

三类奖励：

| 类型 | 做法 | 价值 |
|---|---|---|
| **规则奖励** | 确定性校验正确性 | 精度高，**天然抗 reward hacking** |
| **带参考答案的模型奖励** | 给出参考答案，让 Qwen2.5-72B-Instruct 打分 | 不要求严格格式，**避免纯规则奖励的误判（false negative）** |
| **无参考答案的模型奖励** | 人类偏好数据训出的奖励模型直接打标量分 | 覆盖面最广，提升参与感与有用性 |

> 三者的分工逻辑很清晰：规则管「对不对」，带参考的模型管「规则看不懂的对」，无参考的 RM 管「没有对错只有好坏」的部分。用 rubric 把第三类做得更可控，可参考[《Rubrics 用于 LLM 评测与 RL》](/blog/rubrics-for-llm-eval-and-rl/)。

## 六、强到弱蒸馏：1/10 的算力，更好的结果，还更能探索

> **概念速览**
> - **Off-policy 蒸馏**：学生模仿**教师生成**的回答（序列级）。简单、稳定，适合打底。
> - **On-policy 蒸馏**：学生**自己生成**回答，再把自己的 logits 向教师的 logits 对齐（最小化 KL）。学的是教师在**学生实际会走到的状态上**的分布，信号更密。
> - **pass@1 / pass@64**：采样 1 次 / 64 次至少对一次的概率。前者衡量「稳不稳」，**后者衡量「探索空间有多大」**——pass@64 不涨，意味着模型的能力边界没被推开，只是把已有能力压得更准。

6 个轻量模型（5 dense + Qwen3-30B-A3B）不跑四阶段，而走两步蒸馏：

1. **Off-policy**：把教师在 `/think` 与 `/no_think` 两种模式下的输出混合起来做回答蒸馏，让学生先学会基本推理与**模式切换**。
2. **On-policy**：采样 prompt，学生自行以某种模式生成序列，再与教师（Qwen3-32B 或 Qwen3-235B-A22B）的 logits 对齐，最小化 KL。

**同起点对照实验（Qwen3-8B，均从同一个 off-policy 检查点出发）**：

| 方法 | AIME'24 | AIME'25 | MATH500 | LCB v5 | MMLU-Redux | GPQA-D | **GPU 小时** |
|---|---|---|---|---|---|---|---|
| Off-policy 蒸馏 | 55.0 **(90.0)** | 42.8 **(83.3)** | 92.4 | 42.0 | 86.4 | 55.6 | – |
| + 强化学习 | 67.6 **(90.0)** | 55.5 **(83.3)** | 94.8 | 52.9 | 86.9 | 61.3 | **17,920** |
| + On-policy 蒸馏 | **74.4 (93.3)** | **65.5 (86.7)** | **97.0** | **60.3** | **88.3** | **63.3** | **1,800** |

> 括号内为 pass@64。**两个事实叠在一起才是重点**：
> ① On-policy 蒸馏在**所有六项上都赢 RL**，而 GPU 小时只有 **1/10**；
> ② **RL 的 pass@64 原地不动（90.0 / 83.3），蒸馏则推到 93.3 / 86.7**。
> 换句话说，RL 在这个规模上主要是**把已有能力做锐化**，而从强教师的 logits 蒸馏**真正扩张了学生的探索空间**。这是本文对「小模型该怎么训」给出的最有力论据。

效果验证：**Qwen3-30B-A3B 以不到 1/10 的激活参数追平 QwQ-32B**；Qwen3-14B（思考）在 23 项中与 QwQ-32B 高度竞争；8B/4B/1.7B/0.6B 普遍胜过参数更多的 Qwen2.5 同类。

## 七、评测

> **概念速览**
> - 评测分五维：通用、对齐、数学与文本推理、Agent 与代码、多语言。
> - **采样配置被完整公开**（这类细节直接影响复现）：思考模式 temperature 0.6 / top-p 0.95 / top-k 20；非思考模式 0.7 / 0.8 / 20，presence penalty 1.5；最大输出 32,768，AIME 放宽到 **38,912** 以留足思考空间。
> - **Arena-Hard / AlignBench / WritingBench** 测人类偏好与写作；**BFCL v3** 测函数调用（Qwen3 全部用 FC 格式，多轮评测用 YARN 部署到 64K）；**CodeForces Elo** 每题最多 8 次独立尝试。

## 八、代价与边界：论文自己交出来的三笔账

> **概念速览**
> - **消融（ablation）**：固定其他条件，只看某个阶段/组件带来的净增减。Qwen3 在 Qwen3-32B 上逐阶段测了 Stage 2 → 3 → 4，并引入四个**自建内部基准**：CounterFactQA（反事实问题，考察是否拒绝幻觉）、LengthCtrl（长度控制写作）、ThinkFollow（多轮随机插旗，测模式切换准确率）、ToolUse（单轮/多轮/多步工具调用的意图、格式、参数准确率）。
> - **RULER**：长上下文基准，本质是「大海捞针」式**检索**任务，不太依赖推理。

### 账一：统一模式换走了峰值推理能力

| 基准 | Stage 2（思考） | Stage 3（思考） | Stage 4（思考） |
|---|---|---|---|
| **ThinkFollow\*** | – | 88.7 | **98.9** |
| **ToolUse\*** | 63.3 | 70.4 `+7.1` | **85.5** `+15.1` |
| CounterFactQA\* | 50.4 | 61.3 `+10.9` | 68.1 `+6.8` |
| LengthCtrl\* | 62.6 | 70.6 `+8.0` | 73.5 `+2.9` |
| IFEval strict | 73.0 | 78.4 `+5.4` | 85.0 `+6.6` |
| Arena-Hard | 86.8 | 89.4 `+2.6` | 93.8 `+4.4` |
| **AIME'24** | **83.8** | 81.9 `-1.9` | 81.4 `-0.5` |
| **LiveCodeBench v5** | **68.4** | 67.2 `-1.2` | 65.7 `-1.5` |
| MMLU-Redux | 91.4 | 91.0 `-0.4` | 90.9 `-0.1` |

论文的表述毫不含糊：对知识、STEM、数学、代码类任务，Thinking Mode Fusion 与 General RL **没有带来显著提升**；在 AIME'24、LiveCodeBench 这类难任务上**思考模式反而下降**。推测原因是训练分布被更广的通用任务稀释，削弱了处理复杂问题的专项能力。**「我们选择接受这一性能权衡，以换取整体通用性。」**

> 这笔账值得所有做统一模型的人抄下来：**AIME 掉 2.4 分 / LCB 掉 2.7 分，换来 ThinkFollow 98.9、ToolUse +22.2、IFEval +12.0。** 对产品是明显划算的交易，对刷榜则不是——两种目标函数在此分叉。

### 账二：思考模式在长上下文检索上是负收益

**RULER**（YARN scaling factor=4；思考模式把 budget 限到 8192 以免过度冗长）：

| 模型 | 平均 | 32K | 64K | 128K |
|---|---|---|---|---|
| Qwen2.5-72B-Instruct | **95.1** | 96.5 | 93.0 | 88.4 |
| Qwen3-235B-A22B（非思考） | 95.0 | 95.1 | 93.3 | **90.6** |
| Qwen3-235B-A22B（思考） | 92.2 | 92.3 | 92.0 | 86.0 |
| Qwen3-32B（非思考） | 93.7 | 94.4 | 91.8 | 85.6 |
| Qwen3-32B（思考） | 91.0 | 92.5 | 90.0 | 83.5 |
| Qwen3-8B（非思考） | 89.1 | 91.2 | 82.1 | 77.4 |
| Qwen3-8B（思考） | 84.4 | 80.8 | 78.3 | 72.0 |

结论有两层：非思考模式下 Qwen3 全面胜过同规模 Qwen2.5；但**思考模式一律掉点**。论文的假设是——**检索任务不依赖推理，思考内容反而会干扰检索**。

> 实践推论很直接：**做长文档 RAG/检索时应显式关闭思考模式**，这不是省时间，是提准确率。

### 账三：多语言是「覆盖」而非「精通」

Belebele 上评测 **80 种**支持语言（排除 42 种未优化语言），Qwen3 与同规模 Gemma **相当**，但**显著胜过 Qwen2.5**。例如 Qwen3-32B（思考）在印欧 90.7、汉藏 89.7、南岛 86.7、达罗毗荼 84.5，而 Qwen2.5-32B-Instruct 对应为 85.5 / 82.3 / 70.6 / 67.8。

> 但回看 7.1 的 INCLUDE（78.7）与 MMMLU（84.3）——**语言理解上追平了，区域性知识上仍落后**。「119 种语言」准确的含义是**跨语言的理解与生成能力**，而非每种语言的本地知识储备。

## 九、可带走的 8 条

1. **冷启动阶段要刻意克制。** 目标是植入推理范式而非提分，样本数与步数都应尽量少——训太狠会压掉后续 RL 的上升空间。
2. **RL 数据量不是瓶颈，准入标准才是。** 3,995 条 query-verifier（可学 + 尽可能难 + 覆盖广 + 冷启动未用过），170 步把 AIME'24 从 70.1 推到 85.1，全程零超参干预。
3. **On-policy 蒸馏在小模型上全面优于 RL。** 同起点对照：六项全赢，GPU 小时只要 1/10，且**只有蒸馏能把 pass@64 推上去**。RL 做锐化，蒸馏扩边界——这是选训练方案时的第一判据。
4. **模式融合靠「自己蒸自己」保能力。** Stage 3 的 thinking 数据由 Stage 2 模型对 Stage 1 query 做拒绝采样产生，而非引入外部数据，因此 SFT 不会洗掉前两阶段的推理成果。
5. **格式一致性是能力的一部分。** 非思考模式保留空的 `<think></think>` 块，使内部格式统一、让开发者能用模板强制禁用思考；多轮中随机插旗并约定「遵循最后一个标记」，把模式切换训成鲁棒行为（ThinkFollow 88.7 → 98.9）。
6. **Thinking budget 是涌现能力，实现可以很糙。** 一旦模型同时掌握两种模式，就自然能基于不完整思考作答——截断 + 插一句话即可，无需专门训练。性能随预算平滑上升，32K 以上预计仍有空间。
7. **架构做减法：删 QKV-bias、删共享专家、加 QK-Norm、改全局批次均衡损失。** 删共享专家 + 全局批次均衡的组合意图很明确——**宁可放松均衡约束，也要让专家真正特化**。
8. **统一模型必然要付账，关键是账单是否公开。** AIME'24 −2.4、LiveCodeBench −2.7，换 ToolUse +22.2、IFEval +12.0、ThinkFollow 98.9；思考模式在 RULER 检索上一律掉点；多语言是覆盖而非精通。**把这三笔账明确写进论文，比任何单项 SOTA 都更有参考价值。**

## 小结

把 Qwen3 压成一句话：**统一的代价是可计算的，而统一的收益是复利的。**

三条最该记住的：

- **顺序不可颠倒**：先把思考练到上限，再把不思考 SFT 回来——反过来会洗掉推理能力。
- **RL 的瓶颈在准入标准，不在数据量**：四千条题、170 步、15 个点。
- **小模型优先蒸馏而非 RL**：同起点六项全赢、1/10 算力，且只有蒸馏能推开 pass@64 这条能力边界。
