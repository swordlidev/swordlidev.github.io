> **本文解决一个问题**：2025 年中的现实是——闭源模型在**单项** ARC 能力上已经很强（o 系列的数学、Claude 的改代码），但**同时在三项都强的开源模型不存在**。
>
> GLM-4.5 的全部叙事是「统一」：一个 MoE 基座 + 一次后训练，同时交付 Agentic / Reasoning / Coding，参数量只有 DeepSeek-R1 的一半、Kimi K2 的三分之一。本文按架构、数据、后训练、RL、基础设施、评测六段拆解，重点放在三件可迁移的事：难度课程怎么定义、专家分训 + 自蒸馏为什么优于多目标混训、以及一个 RL 框架为什么必须同时支持同步同置与异步解耦。
>
> 论文：*GLM-4.5: Agentic, Reasoning, and Coding (ARC) Foundation Models*（Zhipu AI & 清华大学，arXiv:2508.06471v1）。模型：GLM-4.5 = 355B 总参 / 32B 激活；GLM-4.5-Air = 106B / 12B，均为 MoE，23T token 多阶段训练。所有对比模型均以 2025 年 7 月 28 日的版本评测。

## 一、一句话定位

> **概念速览**
> - **ARC**：论文把通用模型能力收敛为三类——**A**gentic（调用工具、与真实世界交互）、**R**easoning（数学/科学的多步推理）、**C**oding（真实软件工程）。三者相互依赖：推理是 agent 行为的底座，agent 是编码落地的载体。
> - **MoE（混合专家）**：前馈层拆成许多「专家」，每个 token 只路由到少数几个。于是**总参数**可以很大，但单次前向只算一小部分（**激活参数**）——这就是「355B 总参 / 32B 激活」的含义。
> - **混合推理（hybrid reasoning）**：同一个模型支持两种输出模态——**thinking mode**（先长链思考再回答，用于复杂推理与 agent）与 **non-thinking mode**（直接作答，用于闲聊等低延迟场景）。

交付结果：

- **Agentic**：TAU-Bench **70.1%**、BFCL v3 **77.8%**（基线中最高）、BrowseComp **26.4%**（远超 Claude Opus 4 的 18.8%）
- **Reasoning**：AIME24 **91.0%**、GPQA 79.1%、LiveCodeBench 72.9%、HLE 14.4%
- **Coding**：SWE-bench Verified **64.2%**、Terminal-Bench **37.5%**（超过 Claude Sonnet 4）

12 个 ARC benchmark 平均：**总排名第 3**（agentic 第 2，仅次于 o3；coding 第 3，紧随 Claude Sonnet 4），GLM-4.5-Air 第 6。在「SWE-bench Verified vs 参数量」的散点上，两个模型都落在**帕累托前沿**上。

## 二、架构：深而窄，但注意力头特别多

> **概念速览**
> - **GQA（分组查询注意力）**：多个查询头共用一组 Key/Value，省显存与带宽。表中「96 个注意力头 / 8 个 KV 头」即 12 个 Q 头共享一组 KV。
> - **Partial RoPE**：只对部分维度施加旋转位置编码，其余维度保持无位置信息。
> - **QK-Norm**：对 Query/Key 做归一化，把 attention logits 的数值范围压稳，防训练发散。
> - **Loss-free balance routing**：不靠额外的负载均衡损失，而是给每个专家维护一个可动态调整的 bias 来均衡 token 分配——避免均衡损失干扰主目标。
> - **MTP（多 token 预测）**：额外加一层让模型一次预测后面多个 token，推理时充当「草稿模型」做投机解码。

**两条反直觉的设计选择**：

**① 深 > 宽。** 与 DeepSeek-V3、Kimi K2 相反，GLM-4.5 主动**减小宽度**（hidden dim 5120、路由专家 160 个）、**增加高度**（89 层 MoE）。依据是实验观察：**更深的模型推理能力更好**。

**② 注意力头翻 2.5 倍。** 5120 的 hidden dim 配 **96 个头**。论文坦白这件事**不降低训练 loss**，但在 MMLU、BBH 等推理基准上**稳定提分**——即「loss 不是唯一指标」的一个干净反例。

| | GLM-4.5 | GLM-4.5-Air | DeepSeek-V3 | Kimi K2 |
|---|---|---|---|---|
| 总参 / 激活 | 355B / 32B | 106B / 12B | 671B / 37B | 1043B / 32B |
| Dense / MoE / MTP 层 | 3 / **89** / 1 | 1 / 45 / 1 | 3 / 58 / 1 | 1 / 60 / 0 |
| Hidden dim | **5120** | 4096 | 7168 | 7168 |
| MoE 中间维 | 1536 | 1408 | 2048 | 2048 |
| 注意力头 / KV 头 | **96 / 8** | 96 / 8 | 128 / 128 | 64 / 64 |
| Head dim | 128 | 128 | 192 | 192 |
| 专家总数 / 激活 / 共享 | 160 / 8 / 1 | 128 / 8 / 1 | 256 / 8 / 1 | 384 / 8 / 1 |
| QK-Norm | **Yes** | No | No | No |

> 参数口径：计入 MTP 层，不计入词嵌入与输出层。与 DeepSeek-V3 的并行与架构取舍对照，见[《DeepSeek-V3 实战解读》](/blog/deepseek-v3-training-explained/)。

## 三、数据与多阶段训练：23T token 怎么花

> **概念速览**
> - **预训练 / 中训练（mid-training）**：前者在海量通用语料上学语言与知识；后者位于预训练之后、后训练之前，用**中等规模的领域数据（含指令数据）定向补强**，这里补的是 repo 级代码、合成推理、长上下文与 agent 轨迹。
> - **FIM（Fill-In-the-Middle）**：给出前缀和后缀、让模型补中间，是代码补全场景的原生训练目标。
> - **MinHash / SemDedup 去重**：MinHash 按字面相似度去重；SemDedup 按**文档向量**去重，专门对付「模板批量生成、字面不同但语义雷同」的垃圾网页。
> - **Best-fit packing**：把多条样本拼进固定长度序列时尽量避免截断。预训练**故意不用**（随机截断是一种数据增强），中训练**必须用**（否则会截断推理链或代码仓库）。

### 3.1 四类数据源的处理要点

| 源 | 关键处理 |
|---|---|
| **Web** | 借鉴 Nemotron-CC 按质量分桶：高质桶上采样（最高桶贡献 **>3.2 个 epoch**），最低桶直接丢；额外用 **SemDedup** 清掉 MinHash 清不掉的模板化网页 |
| **多语言** | 自爬 + FineWeb-2，用「教育价值」质量分类器上采样 |
| **Code** | 规则粗筛 → **按语言各训质量模型**分三档，高质上采样、低质剔除；**所有源码施加 FIM 目标**；代码类网页走两阶段检索（HTML code 标签 or FastText 分类器）+ 质量分级，最后用细粒度 parser **重解析以保留代码格式** |
| **Math & Science** | LLM 按「数学/科学教育内容占比」打分 → 蒸馏出小分类器 → 超阈值上采样 |

### 3.2 五段式配方：4K → 32K → 128K

| 阶段 | 内容 | 规模 | 序列长度 |
|---|---|---|---|
| 预训练 ① | 通用语料 | **15T** | 4K |
| 预训练 ② | 代码 & 推理持续预训练（上采样 GitHub 源码、代码/数学/科学网页） | **7T** | 4K |
| 中训练 ① | Repo 级代码（同仓文件拼接学跨文件依赖 + 模型筛过的 issue / PR / commit，commit 以 diff 格式组织） | 500B | 32K |
| 中训练 ② | 合成推理数据（数学/科学/竞赛题，用推理模型合成解题过程） | 500B | 32K |
| 中训练 ③ | 长上下文 + 大规模合成 agent 轨迹 | 100B | **128K** |

### 3.3 超参里值得抄的几条

- **优化器 Muon**（词嵌入、bias、RMSNorm 权重除外）：Newton-Schulz 迭代 5 步、momentum 0.95、update RMS 缩放到 0.2。收益是**收敛更快且能容忍更大 batch**。
- **用 cosine decay 而非 WSD**。早期实验显示 WSD 训出的模型在 SimpleQA / MMLU 上更差，判断为**稳定段欠拟合**。lr 从 0 warmup 到 2.5e-4，一路衰减到 2.5e-5（直到中训练结束）。
- **Batch size warmup**：前 500B token 从 16M 逐步涨到 64M，之后恒定。
- **长度扩展时把 RoPE base 从 10,000 调到 1,000,000**（32K 阶段）。
- **路由 bias 更新率前 15T 为 0.001，之后置 0**；再加权重 0.0001 的序列级均衡辅助损失，防单条序列内极端失衡。**MTP loss 权重前 15T 为 0.3，之后 0.1**。
- 正则化：weight decay 0.1，**不用 dropout**。

## 四、后训练总览：先造专家，再合并

> **概念速览**
> - **SFT（监督微调）**：用「问题–答案」成对数据教模型模仿，建立基本对话、思考与工具调用格式。
> - **专家模型（expert model）**：先分别针对 Reasoning / Agent / General chat 各练一个单项最强的模型。
> - **自蒸馏（self-distillation）**：用这些专家的输出当训练数据，把多个专家的能力「灌」回同一个基座，得到一个通才。好处是避免多目标 RL 直接互相干扰。
> - **拒绝采样（rejection sampling）**：从模型采样大量回答，只保留通过筛选的，当作 SFT 数据。

```text
GLM-4.5 Base
  → 【Stage 1 专家训练】Cold-start SFT → Reasoning RL / Agentic RL / General RL（各练专家）
  → 【Stage 2 统一训练】Overall SFT（自蒸馏融合三类专家，128K 上下文）
                        → General RL（整体打磨 + 病态行为矫正）
  → GLM-4.5（thinking / non-thinking 双模态）
```

SFT 在两个 Stage 的起点各出现一次，但角色不同：Stage 1 的 SFT 是**冷启动**（给 RL 一个能跑的起点），Stage 2 的 SFT 是**融合**（把多个专家蒸成一个混合推理通才）。

### SFT 的五个工程细节

**① 函数调用模板：少转义就是少学习负担。**
主流做法把函数参数塞进 JSON，一旦参数里是**代码**，大量字符需要转义，模型被迫生成海量 `\\`、`\"`。对以函数调用为核心能力的 agent 基座，这是实打实的损耗。GLM-4.5 改用 **XML 风格的 special token 标签**包裹 key/value：

```text
<tool_call>get_weather
<arg_key>city</arg_key>
<arg_value>Beijing</arg_value>
<arg_key>date</arg_key>
<arg_value>2024-06-27</arg_value>
</tool_call>
```

绝大多数代码可以**以原生形态书写、无需转义**，且实验显示函数调用执行性能不受影响。

**② 混合推理靠配比而不是开关。** Overall SFT 收集数百万样本（数学/代码/科学 + 写作/翻译/摘要/闲聊 + 工具使用/真实项目开发 + 长上下文），在 **128K** 上下文下训练；关键是**精细平衡「带完整思考链」与「不带显式思考」的数据比例**——闲聊类不需要长思考，模型因此学会按任务切换两种模态。

**③ 拒绝采样四级流水线**：(1) 删重复/过短/截断/格式不合规；(2) 客观题做正确性校验；(3) 主观题用奖励模型过滤；(4) 工具调用场景校验**调用协议合规 + 轨迹是否到达预期终态**。

**④ prompt 筛选 + 回答扩增（性价比最高的一条）**：

- 按**回答长度**删掉最短的 50% prompt（长度当难度代理）→ **数据减半，数学/科学反而 +2~4%**；
- 对这些难 prompt 每条生成 **4 个回答** → 再 **+1~2%**。

**⑤ Agentic SFT 数据的自动构造（四步）**：收集 agent 框架 / 真实 API / MCP server，并用 LLM 补造模拟工具 → 基于框架与工具合成单步与多步任务 → 用现有 LLM 生成工具调用轨迹（并用 LLM 当**用户模拟器**把多步任务转成多轮对话）→ 多个 judge agent 判定任务是否完成，**只留成功轨迹**。

## 五、Reasoning RL：四条经过对照实验的结论

> **概念速览**
> - **RL / rollout**：不给标准答案，让模型自己生成完整作答轨迹（rollout），由**奖励**打分后调整策略。
> - **GRPO**：省掉价值网络的 RL 算法——对同一问题采样**一组**答案，用组内均分当基线，高于均值的鼓励、低于的抑制。GLM-4.5 用 GRPO 但**去掉 KL 损失项**。
> - **pass@k**：采样 k 次至少对一次的概率。`pass@8=0 且 pass@512>0` 用来精确定义「极难但并非无解」。
> - **奖励方差为零 = 无梯度**：一组 rollout 全对（全 1）或全错（全 0）时，组内基线等于每个样本的分，优势为 0，这一批数据白跑。难度课程的全部动机就是这件事。
>
> 注：本节曲线均来自**小规模实验模型**，不是 GLM-4.5 本身。

**① 两阶段难度课程。** 阶段一用中等难度数据、`samples_per_prompt=16`；阶段二切到**极难数据**（`pass@8=0, pass@512>0`）、`samples_per_prompt=512`。AIME24 Avg@32：**83.4% vs 持续用中等难度的 81.8%（后者已平台化）**。关键约束：阶段二的题**必须来自已验证答案正确的池子**，否则噪声会吞掉收益。

**② 直接在 64K 长度上单阶段 RL，不要渐进加长。** 既有做法是从短到长分阶段放开输出长度；本文的实验相反：SFT 已经让模型习惯生成 64K 级回答，**引入短长度 RL 阶段会让模型「遗忘」长上下文能力**，平均输出长度下降并带来**不可逆的掉点**，最后一个 64K 阶段救不回来。单阶段 64K：**83.4% vs 多阶段 80.6%**。

**③ 动态采样温度。** 温度太低探索不足、太高引入噪声，而固定温度**无法适配策略分布随训练逐渐变尖（熵下降）**的事实。做法：rollout 平均奖励趋稳 → 判定进入收敛期 → 调高温度；同时设质量闸门——周期性在留出验证集上扫一组温度，**取不会使性能从当前最优下跌超过 1% 的最大温度**。

**④ Code / Science RL 的两条经验**（这两个域的 RL 文献远少于数学）：

| 域 | 发现 | 数据 |
|---|---|---|
| **Code** | 损失用 **token 加权平均**而非序列平均：梯度信号更细更稳、**收敛显著更快**，同时缓解序列级奖励固有的**长度偏置**，抑制训练中生成过于简单/重复的 "base case" 样本 | LiveCodeBench 46.5% vs 46.3%（差异主要在收敛速度） |
| **Science** | **只用专家核验过的选择题**，显著优于混合质量数据——即便格式简单如选择题，**严格过滤 RL 数据池仍是关键** | GPQA-Diamond **65.8% vs 62.9%** |

## 六、Agentic RL：可验证性 = 可规模化

> **概念速览**
> - **可验证奖励**：答案或动作能被程序自动判对错（单元测试通过、答案精确匹配），于是奖励密集、可靠、可大规模生成——这是 agentic RL 能 scale 的前提。
> - **多跳 QA**：答案必须跨多个网页/多步推理聚合证据才能得到，用来逼出真实的搜索行为而非记忆背答案。
> - **测试时计算（test-time compute）**：推理阶段多花算力换准确率。推理模型靠**多生成 token**，agent 则靠**多与环境交互几轮**。

**数据来源两条线**：

- **Web search**：(1) 基于**知识图谱多跳推理**的自动化流水线；(2) **human-in-the-loop** 从多个网页抽取内容并**选择性混淆（obfuscation）**，构造出必须联网才能解的题。
- **SWE**：大规模收集 GitHub PR / issue，配成「用户提示 + 可执行单元测试」；全部评测跑在**加固沙箱 + 分布式系统**里，兼顾横向扩展与强隔离。

**目标函数**是组内均值基线形式，**只对模型生成的 token 计损，环境反馈不进 loss**：

$$\mathcal{L}_{RL}(\theta)=\mathbb{E}_{x\sim D}\Big[\frac{1}{K}\sum_{i=1}^{K}\big(r(x,y_i)-\bar r(x)\big)\Big]$$

**三个机制**：

| 机制 | 做法 | 要点 |
|---|---|---|
| **结果监督 + 过程格式惩罚** | 搜索任务用最终答案正确率作为整条轨迹的奖励；编码 agent 用带可验证测试的 SWE 数据。此外**工具调用格式一旦出错即中止轨迹并给 0 奖励** | 结果奖励管「做对」，格式惩罚管「能跑」；实测在 web search + SWE 上的 RL **泛化**到通用工具使用与 Terminal-Bench 等其他任务 |
| **迭代自蒸馏** | agent RL 很慢：先在冷启动模型上 RL 到平台期 → **用 RL 模型的回答替换原冷启动数据**，重训出更强的 SFT 模型 → 在新模型上继续 RL 并提高难度 | 用便宜的 SFT 把 RL 的收益「固化」，再从更高起点开新一轮 RL |
| **按交互轮数做测试时扩展** | browsing effort 从 **8 轮增到 128 轮**，BrowseComp 准确率随之**平滑上升**（至约 30%） | agent 的 test-time scaling 轴是**交互次数**：反复检索难找的信息、写测试做自验证与自纠错 |

> Search Agent 的 RL 在框架侧怎么落地，可对照[《slime 学习笔记（四）：Search Agent RL》](/blog/slime-04-search-agent-rl/)。

## 七、General RL：把「剩下的问题」逐项清掉

> **概念速览**
> - **RLHF / RLAIF**：奖励分别来自**人类偏好**标注训练的奖励模型 / **AI 评判**（LLM 按 rubric 打分）。再加上**规则奖励**（确定性校验），构成三源反馈。
> - **Critique model**：先写评述再给判定的评判模型，比直接打分更难被投机取巧。
> - **Reward hacking**：模型找到钻奖励函数空子的捷径，分数涨了但质量没涨。

| 子阶段 | 做法 | 关键数字 |
|---|---|---|
| **Holistic RL** | 构造约 **5,000** 条均衡 prompt，覆盖 **7 个一级 / 33 个二级 / 139 个三级**类别；人类偏好奖励模型 + 模型反馈（按「有无客观答案」设计两套 rubric）**融合** | 融合两源以互相补短 |
| **Instruction Following RL** | 建 **7 大类 / 151 小类约束**的细粒度 taxonomy（内容要求、格式规则等），每类都配难样本；反馈 = **确定性规则 + 奖励模型 + critique 模型** | SysBench-ISR 随奖励同步上升 **64.8 → 77.2**；**到约 1,000 步未见明显 reward hacking** |
| **Function Calling RL** | **Step-wise 规则式**：标注每步 ground-truth 调用，奖励为**严格二值**——格式正确**且**与标答完全一致（名称、参数、每个字段）才给 1。<br>**端到端多轮**：先生成完整轨迹再按任务完成度给奖励，覆盖①单轮多步（MCP 自动合成任务 + AgentGym 等可运行环境）②多轮多步（还需与 **LLM 模拟用户** 交互才能拿到完整任务信息）；完成度由环境规则或 **LLM Judge Agent** 判定 | step-wise 因输出长度与收敛速度相近，可直接并入通用 RL 框架；端到端则**先训专家再蒸馏进主模型** |
| **Pathology RL** | 治语言混杂、过度重复、格式错误。这类病态**发生率常 <1%**，在通用 RL 里惩罚它极其低效 → **专门挖「高概率触发」的 prompt 组成定向数据集** | 用小数据集高效压低残余错误率 |

> 设计逻辑：严格二值奖励强行把「格式正确性」也一并训进去，提升真实交互中的可用性与鲁棒性；而端到端多轮的存在理由是——**step-wise 把任务拆成静态预设流程，模型没有机会自主探索、规划与应对意外**。

## 八、RL 基础设施：slime 的一个核心判断

> **概念速览**
> - **Colocated（同置）vs Disaggregated（解耦）**：训练引擎与推理（rollout）引擎放在同一批 GPU 上，还是各占独立 GPU。
> - **同步 vs 异步**：同步要等整批 rollout 全部完成才更新权重，**最慢的那条轨迹决定节奏**；异步让 rollout 持续产出、训练侧定期同步权重。
> - **动态采样（dynamic sampling）**：丢弃奖励无方差的样本组，并即时补采，避免浪费算力。
> - **FP8 / BF16**：低精度数值格式。训练对精度敏感用 BF16，**生成环节可用 FP8 换吞吐**。

**核心判断：不同 RL 任务需要不同调度，所以一个框架必须同时支持两种模式。**

| 任务类型 | 架构 | 理由 |
|---|---|---|
| 通用 RL / 推理 RL（数学、代码生成） | **同置 + 同步** | 训练与推理引擎在同一 worker，配合动态采样可**显著降低 GPU 空闲** |
| Agentic RL（尤其 SWE） | **解耦 + 异步** | rollout 耗时长、涉及复杂系统交互；把 rollout 组件直接暴露给 agent 环境，训练/推理 GPU 独立调度，**环境得以不间断产数据而不被训练周期卡住** |

两种模式靠 **Ray** 的资源调度灵活放置引擎，从而**共享同一套底层训练与推理优化**。

**slime 三模块**：**Training（Megatron）** 从 Data Buffer 读数据、训完与 rollout 同步参数；**Rollout（SGLang + Router）** 产出新数据（含奖励与 verifier 输出）写回 Buffer；**Data Buffer** 作为桥梁，管 prompt 初始化、自定义数据与 rollout 生成策略。

**另外三条工程要点**：

- **混合精度 rollout**：训练 BF16，推理 FP8。每次策略更新后，参数分发给 rollout **之前**做**在线 block-wise FP8 量化**，显著提升数据收集吞吐。
- **高并发 Docker 运行时**：每个任务一个隔离环境，大幅压低 rollout 开销。
- **统一 HTTP 端点 + 中心化数据池**：既有 agent 框架五花八门（用它们既提性能又保训推一致），而大多框架的 rollout 都是 **message-list** 格式 → 全部轨迹统一入池，**任务特定的 rollout 逻辑与 RL 训练彻底解耦**，并在池上做任务级过滤与动态采样。

> slime 的实现细节见系列笔记：[（一）上手](/blog/slime-01-getting-started/)、[（二）核心流程](/blog/slime-02-core-pipeline/)、[（三）算法设计](/blog/slime-03-algorithm-design/)。

> - **Base 模型评测**：只测预训练末期的裸基座（未经指令训练），反映「天花板」与数据配比取舍。

## 十、可带走的 9 条

1. **「统一」是架构约束，不是营销词。** 一个 MoE 基座同时吃 ARC 三类能力，靠的是数据配比 + 专家分训 + 自蒸馏融合，而不是三个模型拼起来。
2. **深而窄 + 多头注意力。** 减宽增深提升推理；注意力头翻 2.5 倍**不降 loss 但提分**——训练 loss 不是选架构的唯一判据。
3. **难样本的边际收益极高。** 按回答长度砍掉一半简单 prompt，数学/科学反而 +2~4%；对剩下的难题每条多采 4 个回答再 +1~2%。
4. **RL 的难度课程要精确定义。** `pass@8=0 且 pass@512>0` 是「极难但非无解」的可操作判据；且阶段二数据**必须答案已核验**。
5. **别做渐进式长度 RL。** SFT 已经把模型调到 64K，再从短长度 RL 起步会让它「遗忘」长输出能力，掉点**不可逆**。直接在目标长度上单阶段跑。
6. **工程细节会直接变成能力。** XML 风格函数调用模板消掉代码转义；token 加权平均损失加速 code RL 收敛；专家核验选择题把 GPQA 拉高近 3 个点。
7. **一个 RL 框架必须同时支持同步同置与异步解耦。** 推理类任务靠同置 + 动态采样填满 GPU；agentic 任务必须解耦，否则长尾 rollout 卡死整个流水线。统一的落点是 **message-list 数据池 + HTTP 端点**。
8. **低发生率缺陷要单独立项。** 语言混杂、重复、格式错误发生率 <1%，在通用 RL 里惩罚它极其低效——专门构造「高概率触发」数据集才划算。
9. **自建评测的价值在于敢报短板。** CC-Bench 对 Claude Sonnet 4 是 40.4% : 50.0%、BrowseComp 26.4 vs o3 的 49.7、HLE 14.4 落后一截、base 模型 GSM8K/MATH 明显回落——这些数字比任何排名都更有信息量。

## 小结

把 GLM-4.5 压成一句话：**三类能力不是靠一次多目标混训硬捏在一起的，而是先分头练到最强、再用自蒸馏合并，最后用一轮通用 RL 收尾。**

三条最该记住的：

- **先造专家再合并**，避开多目标 RL 的互相干扰；合并阶段的关键参数是「带思考 / 不带思考」的数据配比。
- **难度是 RL 的第一超参**：零方差的 rollout 组等于白跑，`pass@8=0 且 pass@512>0` 把「极难但非无解」变成可执行判据。
- **基础设施的分叉点是任务形态**：推理 RL 要同置同步填满 GPU，agentic RL 必须解耦异步，否则长尾轨迹决定全局节奏。
