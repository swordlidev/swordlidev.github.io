> RSI（Recursive Self-Improvement）：用 AI 去改进 AI 的开发过程，直到系统能自主设计、训练出自己的后继者。本文只谈已落地的数据、可验证的机制和已知的失效模式，不做科幻推演。

## 一、2026 年发生了什么

| 时间 | 事件 | 关键信号 |
|------|------|---------|
| 2026.06.04 | Anthropic《When AI Builds Itself》 | 代码库 **>80% 由 Claude 编写**；提出可验证的暂停机制 |
| 2026.09.06 | OpenAI "自动化研究实习生"达成 | Agent 工作量 **>3× 人类研究员**；目标 2028.03 全自动 AI 研究员 |
| 2026.09.06 | Pachocki《An Alien Mind》 | "没有任何实验室在对齐与监控上做到足够充分" |

配套信号：ICLR 2026 首设 RSI Workshop；Recursive Superintelligence（田渊栋 + Richard Socher）成立，估值 46.5 亿美元。

RSI 不是单一能力，而是一条**反馈回路**：

```text
模型 → 写代码/设计实验 → 产出更强模型 → 回路增益 g
  g < 1：改进逐代衰减，收敛到天花板（∑ gᵏ 收敛）
  g > 1：改进逐代放大，进入加速区（∑ gᵏ 发散）
```

全部争论都围绕一个问题：**当前系统的 g 到底在 1 的哪一侧，以及什么决定了 g。**

## 二、深读：Anthropic《When AI Builds Itself》

Marina Favaro 与 Jack Clark 撰写，The Anthropic Institute 2026.06 发布。价值在于**第一次公开头部实验室 RSI 进程的内部数据**。

### 2.1 四组内部数据

| 维度 | 数据 | 口径与基准 |
|------|------|---------|
| **代码占比** | 2026.05 合并进库的代码 **>80% 由 Claude 写** | 2025.02 Claude Code 预览版前为个位数；含脚本/实验代码领导层估 >90%，80% 是保守的生产口径 |
| **工程吞吐** | 2026 Q2 人均日合并代码量 = 2024 年的 **8×** | 行数只测量不测质量，几乎确定高估；130 人调研主观中位数约 **4×** |
| **开放任务成功率** | 六个月 26% → **76%**（+50pp） | 衡量最无约束的工程任务 |
| **优化加速比** | 代码优化任务 2025.05 ~3× → 2026.04 **~52×** | 熟练研究员要 4–8 小时才做到 ~4× |

两个佐证：2026.04 Claude 单次修复 800+ bug，把某类 API 错误降低 1000 倍（人类估需 ~4 年）；GitHub 全网提交从 2025 全年约 10 亿次升到 2026 年中每周 2.75 亿次。

外部基准（METR 口径）也对齐：AI 能可靠完成的任务时长**每约 4 个月翻一番**（此前为 7 个月）——2024.03 约 4 分钟 → 一年后约 1.5 小时 → 再一年约 12 小时。时长翻倍周期本身在缩短，是 g 上升的直接证据。

### 2.2 能力画像：缺口在"品味"不在"手艺"

| 层面 | 现状 |
|------|------|
| 工程 | 人类给**目标**即可，无需给方法 |
| 执行明确实验 | Claude 匹敌或超越人类 |
| 代码质量 | 2025 底逊于人类 → 现在大致持平 → 预期一年内严格超越 |
| **选题 / 判断力** | **仍是人类比较优势**：判断哪些问题重要、哪些结果可信、何时是死胡同 |

这条"品味缺口"就是今日 AI 与"能自主设计后继者"之间的全部距离。研究方向判断测试：最佳模型击败人类选择的比例从 2025.11（Opus 4.5）的 51% 升到 2026.04（Mythos Preview）的 64%——缺口在缩小但未消失。

### 2.3 三种未来

1. **S 曲线封顶**：判断力未必能靠 scaling 获得，且受能源/算力/芯片制约。Anthropic 判定**可能性最低**，但留给社会的适应时间最多。
2. **复合效率增益**（判定**最可能**）：开发大幅自动化、人类仍掌方向。100 人做 1 万–10 万人的活，但撞上**阿姆达尔定律**——加速一环只是把瓶颈移到别处（现实里人类代码审查已成新瓶颈）。
3. **完全 RSI**：进步速度几乎只由算力决定，人类退到监督/验证层。对齐在此最不确定：可能自行收敛到对齐解，也可能错配逐代累积至失控。

关键论断：**即便模型永远得不到"研究品味"，保守解读仍指向复合加速**——因为研究进步大多是"渐进式苦功"（99% 汗水），而苦功正被自动化。所以争论的是"多快"，不是"会不会"。

### 2.4 政策主张：可验证的暂停选项

- 支持让世界保留**放缓/临时暂停前沿开发的选项**，并构建**可验证机制**，确保各方真停、坏行为者无法借暂停暗中抢跑。
- **前提是协同**：别人以可验证方式同步放缓，Anthropic 才跟进；单方面减速只会让最不谨慎者领先。
- **难点**：AI 可核查性远难于核武——训练运行易隐藏、输入通用、违约诱因巨大。核查类条约（如《中导条约》）历史上要数十年建立信任，"而我们没有那么多时间"。被外界读作"AI 不扩散条约"雏形。

> 一句话：用内部数据把 RSI 从思辨拉进现实，结论是"尚未实现、也非必然，但可能来得比多数机构准备得更早"，据此主张提前建可验证的协同减速机制。

## 三、综述框架：两轴分类 + 验证层级

Chen, Wang, Qu (2026) — [arXiv:2607.07663](https://arxiv.org/abs/2607.07663)，调研 **1,250 篇**论文（2024–2026）。

**两轴分类**

- 轴一（改进什么）：部署时行为（输出 / scaffold）→ 训练时策略（权重）→ 评估器 → 研究过程
- 轴二（谁来验证）：Human-in-the-loop → Human-on-the-loop → 完全闭环

**验证层级（Verification Hierarchy）** —— 全文最有用的结论：

```text
强 ↑  形式验证器   证明检查器、类型系统        —— 可判定，零假阳性
  │  执行反馈      测试、编译器、benchmark     —— 客观但覆盖不全
  │  学习型评判器  奖励模型、LLM-as-Judge      —— 可被 Goodhart、可被攻击
弱 ↓  内在信号      置信度、自洽性              —— 与正确性弱相关甚至反相关
```

机制上，自改进等价于"**生成候选 → 用验证器筛选 → 把筛选结果固化进模型**"。信号可靠性决定了这个回路是提纯还是污染：

- 用**强于生成器**的验证器筛选 → 期望质量上升（回路增益 g>1）。
- 用**自身信号**当验证器 → 等于拿模型自己的偏好当真值，回路收敛到模型的**不动点**而非真值，Goodhart 必然发生。

这解释了为什么代码/数学跑得最快：它们天然坐在层级顶端（测试、编译器、可运行 benchmark 提供近乎零假阳性的信号），而开放域只有学习型评判器，g 很难 >1。

## 四、技术方向：四条可落地路线

### 4.1 Harness 自进化（改 scaffold，不改权重）

Lilian Weng (2026.07) — [Harness Engineering for Self-Improvement](https://lilianweng.github.io/posts/2026-07-04-harness/)

核心区分：**Model 自进化（改权重）⊥ Harness 自进化（改 prompt / 工具 / 工作流）**，两者正交、可叠加。工程意义是 harness 侧改进**不需要重训**、迭代成本极低，常常是短期 g 的主要来源。

| 系统 | 自修改机制 | 改进目标 |
|------|-----------|---------|
| **Gödel Agent** (ACL'25) | 运行时 monkey-patch 自身行为逻辑（读写自己的代码对象） | Prompt / Workflow |
| **Polaris** (2026) | Gödel Agent + 经验抽象 + 最小补丁修复（只打最小 diff） | 策略修复 |
| **Darwin Gödel Machine** (ICLR'26) | 编码 agent 改写自身代码 → 存入 **archive** → 开放式进化选择 | 全栈代码 |
| **HELIX** (2026) | harness 演化与模型训练**耦合**迭代 | Scaffold + Weights |

DGM 的关键不是"会改自己"，而是**保留失败分支的 archive + 开放式选择**——避免贪心地沿单一方向优化而陷入局部最优，这正是对抗 diversity collapse 的手段。

### 4.2 AlphaEvolve：LLM + 进化搜索的闭环

DeepMind (2025.05)，FunSearch 升级版。

```text
LLM (Gemini) 生成程序变体
   → 自动评估器打分（必须可自动评分 = 强验证器）
   → program database（island model 维持多样性）
   → 采样高分程序作为下一轮 prompt 的灵感
```

它已经**反哺自身**：发现的算法优化了 Gemini 的训练内核，构成"AI 发现的算法 → 改进训练 AI 的 AI"的初步闭环。成立前提同样是验证层级——**只在能自动精确打分的问题上有效**（矩阵乘法、调度、kernel），这就是为什么它在算法领域成功而不是在开放研究上。

### 4.3 Solver-Verifier Gap：训练时自改进的理论上限

[arXiv:2507.00075](https://arxiv.org/abs/2507.00075)，首次对自改进训练动力学建模。

直觉：自改进靠"生成 N 个候选 → 用 verifier 挑好的 → 拿去训 solver"。单步能榨出的信息量正比于

$$
\Delta \;\propto\; \underbrace{\text{acc}_{\text{verify}}}_{\text{能挑对的概率}} - \underbrace{\text{acc}_{\text{generate}}}_{\text{直接生成对的概率}}
$$

- $\text{acc}_{\text{verify}} \gg \text{acc}_{\text{generate}}$（判断比生成容易，如数学/代码）→ 筛选带来净信息，自改进有效。
- 两者趋同 → $\Delta \to 0$，筛选不再引入新信息，**自改进饱和**。

这是验证层级的训练时版本，也量化了"为什么有强 verifier 的领域才跑得动"。

### 4.4 临界阈值：回路什么时候持续

[arXiv:2607.04277]。把第一节的增益 g 形式化：存在临界点 $g_c$，$g<g_c$ 改进衰减至零、$g>g_c$ 持续加速。实测当前系统**在阈值附近震荡**——这正是三种未来都成立的原因，差一点就翻向不同分支。

## 五、三大失效模式及其成因

| 失效 | 数学成因 | 对策 |
|------|---------|------|
| **Model Collapse** | 在自生成数据上递归训练，每代采样引入统计近似误差 → **分布尾部逐代丢失、方差单调收缩**（Shumailov, Nature 2024：第 7–8 代崩溃） | 混入真实数据锚定分布；多样性正则 |
| **Self-Confirming Loop** | 用自身信号当验证器 → 回路收敛到模型不动点而非真值，偏见被正反馈放大 | 外部锚定评估；**生成器与评估器解耦** |
| **Diversity Collapse** | 自对弈/贪心选择使策略空间单调收缩 → 探索坍塌、过早局部最优 | 种群多样性维护（island/archive）；对抗样本注入 |

三者同根：**用不高于生成器的信号去监督生成器**（违反验证层级），回路增益被虚高估计，实际在污染而非提纯。

## 小结

1. **一个变量统摄全局**：回路增益 g。g 由验证信号可靠性决定，因此 RSI 先在"有强 verifier"的代码/数学上突破，在开放域停滞。
2. **缺口在品味不在手艺**：Anthropic 数据显示工程/执行已接近人类，差的是选题与判断力；但即便品味缺口永不填平，保守解读仍指向复合加速——争论的是速度而非方向。
3. **所有失效同根**：用不高于生成器的信号监督生成器，就会把污染误当提纯。工程上的通解就是**生成器与验证器解耦 + 外部锚定 + 多样性维护**。
